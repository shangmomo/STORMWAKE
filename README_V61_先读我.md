# STORMWAKE V61 基础体验优化版

V61 在用户提供的 V60 全量工程上继续修复，沿用自研 JavaScript/WebGPU 引擎、原荷兰船、现有世界与房间服务。这个版本是可运行的阶段交付，尚未完成两份规格的全部验收。

## 启动

解压整个工程后，双击 `00_START_STORMWAKE_V61.cmd`，选择单人、多人创建或多人加入。保留启动终端。单人不需要安装 npm 包；需要 Python 3.10+ 和支持 WebGPU 的 Chrome/Edge。多人房主另需 Node.js 22+，局域网使用房主 IPv4 和 TCP 5174。

```powershell
python start_v61.py --mode solo
python start_v61.py --mode host
python start_v61.py --mode join --room 192.168.1.20:5174
```

旧 V60 启动入口继续兼容。源码目录名称来自解压基线，不影响 V61 启动。

## 本轮落地的修复

- 修正 QA 启动竞态：等待真实开场界面，按键进入后确认界面已经隐藏；游戏使用 loading / awaiting_start / playing 状态。停止把过早发送 Enter 当作进入游戏。
- STORMWAKE 不再自动弹出旧钓鱼教程；F1 的教程入口连接航程日志。
- 修复干舱白线的实际来源：水下后处理关闭时同时停止镜头折射、介质判断及亮边合成，外海仍正常绘制。
- 从当前显示的船体、船长室及货舱网格烘焙船局部 BVH，角色移动使用连续胶囊检测与滑动；动态门板加入同一移动查询。普通船长室行走不再调用旧的邻近空格寻位恢复。
- 原门增加扫掠防夹；攀爬途中按 Esc 会沿已走过的路径返回。门板尚未让开时拒绝进入。
- 修复货舱梯口 E 被锚机抢走；瞄准对象优先于附近高优先级设备；装备交互增加静态几何遮挡检查，并提供 `interactionTrace()`。
- 岗位等待服务器确认，0.5 秒提示等待、1.5 秒超时取消；迟到确认、拒绝、断线清理和远端输入过期均有处理。
- 当前荷兰船的 1/2/3/4 人绞盘效率为 1/1.5/2/2.5，反向操作抵消；四个站位跟随共享把手转动。
- 绞盘收尽或放尽后有机械止动，继续按键不会让把手空转。可用 `maxFps` 设置渲染上限；后台页面降低帧率以减少多客户端竞争。
- 新版房间验证荷兰船岗位的局部位置与楼层；船体姿态同步增加完整四元数、垂直速度及角速度，货物/岗位距离查询可跟随横摇与纵摇。
- 船舱常亮暖灯与实体灯具共用坐标；货舱增加木纹；室内材质使用干燥光照。室内停止海怪武器瞄准/开火，减少无关操作提示。
- HUD 默认折叠详情，操作提示移出左栏；上船时收起家园和钓鱼钱袋提示，详情与航程日志仍可展开。
- 修复本地离线服务的导游状态 404、favicon 请求和 Windows 扩展测试的临时目录路径；QA 独立管理房间子进程，避免遗留占用端口。

## 验证与证据

```powershell
npm ci
npm run test:v61:extended
npm run build
python tools/autoqa/runner.py --quick --all-scenes --route-cycles 20 --headed --browser msedge
python tools/autoqa/runner.py --clients 4 --headed --browser msedge
```

本轮确实在 Windows Edge 上运行了 WebGPU 场景，并保存截图、视频、输入操作结果及多端状态。历次成功与失败报告都保留在 `qa/V61/`；最终有效证据及未完成条目以 `docs/V61_ACCEPTANCE.md` 和 `qa/V61/acceptance_cases.csv` 为准。运行日志里的逻辑通过、截图采集与人工视觉判断分别记录。

单人通路复测和四人短测分别记录；四客户端验收使用 30 FPS 上限，不能据此认定 1080p 60 FPS 性能达标。17 项新增行为检查、既有历史回归、Dawn 引擎 smoke、2 项 HTTP 并发/连接复用测试与生产构建均有独立日志。图形驱动、着色器首次编译与多客户端内存仍会影响加载时间。

## 重要边界

角色仍沿用 V60 的缩小船员比例，尚未完成成年人体尺度和原船空间的统一重拓扑。胶囊/BVH 已接入，但不能据此宣称所有跳跃、家具、梯子、双人错身和极端船倾角都无穿模。门/梯的引导通行仍保留现有路径机制，尚非完整的人体攀爬 IK。

54 组水密工况、四人 45 分钟连续任务、完整战斗维修录像、海怪骨骼接触伤害、潜艇重制及五类新航程均未整体签收。新 GDD 的扩展内容按其前置规则保留在待实施列表中，没有用占位实现冒充完成。原模型及许可证继续随包保留；本轮没有引入第三方新模型或音频。
