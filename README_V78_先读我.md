# STORMWAKE V78 — 连续世界与稳定性修复

使用 7-Zip 完整解压，运行 `00_START_V78.cmd`。不需要补丁，也未删除 V77 既有模型。单人 Python 3.10+ 和支持 WebGPU 的 Chrome/Edge；房主额外 Node.js 22+。升级前建议备份原浏览器本地存档。

## 已实现
- 陆地角色使用合并后的三角网格查询（统一接触求解），不再依次求解各独立网格后覆盖位置；最大 0.12m 子步，限制箱体/圆柱修正并复查网格，拒绝无效坐标及大于 3m 的单次步进。短小非可走物体不再当作可跨越台阶。步行地面支持限制抬升、下坡贴地；游泳增加三角网格扫掠。
- 第三人称镜头对建筑盒体及网格射线检测，阻挡时缩短镜头距离。移动动画依据实际水平位移，不再因持续按住方向键而在墙前一直跑；角色转身限速；单次动作按实际片段长度结束，已结束的动作可重新播放；腾空时暂停脚底贴地校正。没有新增未验证的全身骨骼重定向。
- 沉岩洞在原首领区域后新增连续下降、弯曲的深层岩廊及岩心调查点（击败原首领后可领取一次95金币，钱包回执防重复），沿同一入口返程；增加支撑和灯火。整个岩壳为一体连续网格，原始地形/岩壁相互约束。洞口 -445 到末端 -603；测试路线 -440 至 -596 往返，最大坡度约21.4%，最低地面37m，5496个碰撞三角面。当前仍是单一地形上的覆岩洞廊，不是独立完整多层地下城；没有地下湖、升降机、Lurker战斗。
- 酒馆使用完整原始三角网格，补回原来排除的高处几何；酒馆和工坊进门/服务/返回用新角色控制器复测。上层楼梯、逐间房间、屋顶全通行尚未逐条验收。大型建筑碰撞构建分批让出执行权，多个V76站点排队处理，几何/碰撞完成后一起提交。仍有较大同步排序、GPU上传和内存开销，不能宣称消除了所有长帧。
- GLB载入60秒超时、错误长度/截断检查；启动180秒无进度提示；每帧异常或GPU设备丢失时停止模拟与输入，显示明确的重新加载入口，不继续处理半更新的世界。浏览器彻底挂死或硬件故障无法依靠游戏内JS自动处理。
- 单人陆地非战斗状态按 F6，尝试回到8米范围内上一个经过盒体及网格净空检查的记录点。不会强制传送船只或潜艇，也不是无限距离传送。若没有合适记录点，仍可能需要重新载入。非有限的本地位置/速度尝试恢复上一个安全记录。新服务和新增生态的服务器权威联机机制仍未完成。

## 验证与剩余限制
`npm run test:v78` 执行新增测试和历史回归。实际日志在 qa/V78-*。历史62项回归（6+7+7+42）与原四客户端WebSocket在本轮主改动后通过；后续输入和动画修正由新增专项覆盖。浏览器曾使用普通headless、SwiftShader、Ozone headless和Xvfb；EGL/GPU初始化或页面访问被管理员策略阻止，未成功进入真实游戏场景，不能称为WebGPU实机视觉验收或帧率验收通过。HTTP启动及新脚本与酒馆模型访问通过。

完整地下世界、所有建筑楼层、所有角色动作（尤其衣物穿插与脚部接触）、大怪动画、联网新生态/交易、真实帧率、长时间多玩家压力测试仍未完成。未使用新的劣质替代模型，保留既有资源和授权记录；既有部分低模、酒馆及铁匠授权详情待核验问题仍在。
