# STORMWAKE V40 — 代码修复与严格验收报告

**状态：程序修复候选版；未通过 WebGPU 浏览器实机画面和人工手感验收，不得标为最终无缺陷成品。**

## 1. 源码基线与边界

- 来源：用户已有 V39 Voyage Co-op M1 的完整源码包；V39 原件未覆盖。
- 保持 `python start_v38.py` 启动入口，并新增 `python start_v40.py` 别名及原 M1 航程。局域网沿用 `python run_v39_coop_windows.py`。
- 与 V39 原始 ZIP 比较，`src/engine/`、`src/ocean/`、`src/sky/`、`src/post/` 共 89 个文件逐字节完全相同，未重写 WebGPU/WGSL/FFT/天空/后处理内核。
- 不重置老版游戏的钓鱼等存档。航程/货物原子快照新键为 `stormwake.m1.snapshot.v2`，并保留旧 `stormwake.cargo.v1` 迁移。

## 2. 已复现并修复

| 问题 | 修复 | 证明 |
|---|---|---|
| 完成第一次航程后，第二次挖掘卡在 0%，无法再获得宝箱 | 新接受航程清空 `DigSite.completed/progress`，服务端同步重置挖掘时间和旧箱状态 | 连续两次从接任务、四秒挖、拾取、上船入舱、卖箱走通；货币累计 240，重复卖不重复发奖 |
| 带宽/帧时序不同步，瞬时炮击、锚、桶事件被下一帧仅含轴输入的包覆盖 | `ShipStations.setInput` 对一次性指令锁存至消费；联机侧 60ms 发送窗口聚合 | 一帧开火、后续空包仍只触发 1 炮；锚开关与水桶事件不丢 |
| 炮击后立即按 R 装弹没有反馈 | 增加 `reloadQueued`，冷却结束时自动上弹 | 冷却前按 R，完成后可开下一炮且不会无限连发 |
| 任务与宝箱分别存档，程序中途退出后出现“已挖但箱没了”或“已入舱但无法卖” | 原子保存任务与货物，并在载入时修复允许的中断状态 | 测试强制注入损坏的 `dug/stowed` 快照并完成复原 |
| 船沉没后单人被卡在不可恢复状态 | 仅单人新增回海风镇整备按钮与恢复逻辑；重置船/敌船/破损/未完成宝箱，保留潮币 | 沉船 → 恢复 → 重新接任务；同一沉船不能重复恢复 |
| 靠船舷按 E 无法下船，因为维修桶、舷炮与离船点重叠 | M1 离船改为 `Shift+E`，岗位保留普通 `E`，输入消费统一优先级 | 真实 `Player.updateDeck`：普通 E 不错误下船，Shift+E 可从重叠舷侧离船 |
| 船坞仍提示“一人全控”并允许中途换船，致岗位相对坐标失效 | M1 禁止中途船型替换，提示原驾驶在 `?stormwake=0` | 本地逻辑和回归检查 |
| AI 返航与舵帆物理可能出现数值不稳 | 使用生产 `BoatController/BoatModel/TerrainData/CrewAI/ShipStations` 模拟去程、停船、逆风返港 | 60 FPS、约 195 秒上限、双向航段均抵达，无传送和 NaN；水面固定平水代替 GPU FFT |

## 4. 尚未通过、禁止对外声称通过的门槛

1. **真实浏览器游玩**：本容器 Chromium 所有导航（包括 localhost/data/file）均被策略以 `net::ERR_BLOCKED_BY_ADMINISTRATOR` 拒绝；无法加载页面，更无法验证鼠标指针、UI 遮挡、船员实际站位、图形帧、脚底碰撞、实战手感。不是游戏 WebGPU 测试通过。
2. **Vite 生产构建**：容器中的 Vite/native `webgpu` 依赖不存在；`npm run build` / `npm test` 对应依赖测试不能完成。Python 免 npm 启动路由已单独检查，不可代替图形运行。
3. **2 台独立 Windows 设备局域网体验**：两 Node 客户端逻辑协议通过，但真实不同电脑、有网络波动、真人同时操作的实际联机体验尚未验证。
4. **所有视觉、碰撞、音频和自由操作路径**：无实机视口/音频输出，不得保证零故障。
5. **联机沉船救援**：本轮只对单机实现恢复，联网沉船尚需房主重启房间；这项属于明确未完成的体验缺陷。

- 从港口单人 AI 开船抵灰苔岛，玩家上岸连续按住 E 四秒挖宝，搬箱返回舱位，返港兑现。
- 紧接着再做第二轮航程，币数由 120→240；卖同一箱第二次应无效。
- 炮位连续点击、提前按 R、维修/水桶/锚操作；检查炮弹、船体受损、按钮状态与镜头。
- 有意让船沉没，验证单机回港整备按钮可点击且重新开始。
- 打开两个真实浏览器，进同房分别占舵/帆，检查船体同步、离岗、炮击与多人挖宝。
- 验证海面 FFT、深海潜艇、陆地伙伴、村民脚底、帧率和 HUD 遮挡均无重大回归。

**结论**：已修复若干能复现的真实程序缺陷，但因图形环境被行政策略阻断，本版只能作为**可复现程序验证的 V40 修复候选包**；并不符合“亲自 WebGPU 游玩直到完全无问题”的最终验收条件。
