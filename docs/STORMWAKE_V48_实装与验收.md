# STORMWAKE V48 — Dutch Ship 游玩闭环修复与验收记录

**基线：** 用户上传的 V47 完整工程（含 21 项已转换 CC0 GLB、原有海域、任务、海战、多人通信源码），在原项目基础上直接修改；不是独立的截图演示或空壳模板。

**重点：** 统一坐标与人物比例，取消 Dutch Ship 原有的 `E` 瞬移登船，加入可见舷梯攀爬、甲板自然落海和船长室，接通手持/放下物品与炮弹装填。保持旧船模式兼容。

## 操作与场景复验手册

0. **启动：** 完整解压，运行 `START_STORMWAKE_V48.cmd`，确认地址 `http://127.0.0.1:5173/?stormwake=1&heritageShip=1`。必须有 WebGPU 支持的 Chrome / Edge。游戏模式为原项目的 WebGPU 引擎，**不是** Unity 工程。
1. **体型：** 从码头对比人和船，检查人类身高约 1.75m、船长约 22m；船员不会跟船壳一起放大 2–3 倍。
2. **自然登船：** 走到岸边跳水，游到两舷可见的木梯附近，面向船按 `W` 或 `Space` 连续向上攀爬。不要按 E；若不接近实体梯不会登船。
3. **自由跳海：** 走到船舷，跳过护栏，落入海中。应保持船速惯性，短暂防止刚跳海就被舷梯自动抓回。
4. **甲板与船长室：** 从尾楼走到船首；靠近后部船长室的门按 `E` 开门，进入、看航图和日志、关门；关门时不应穿过门板。
5. **船舱：** 从主甲板舱口按 `C` 下舱；从舱内梯口按 `W` 上舱；检查摄像机和角色位置。
6. **航行：** 去操作真正的舵轮/帆索/绞盘岗位，各自按 `E` 操作；确认在锚起、帆张开、舵输入之后船的位置/航向变化，而不是只有 HUD 数字变化。
7. **炮战：** 先到弹药箱 `E` 拿一发炮弹；按 `G` 放下并 `E` 捡回，确保单个实体不增殖；在炮位 `E` 上岗，`R` 装填，约 2.8s 后开火。检查后坐、弹丸生成点、真实击中与再装填。
8. **破口与排水：** 产生船体炮击破口，从维修箱 `E` 取木板，切 `6` 后到破口附近按住左键补洞。找到水桶架 `E` 取水桶，切 `2`，舱底舀水后到舷边泼出；不得无道具凭空修复或泼水。
9. **长时间与暴风：** 快速转舵、持续摇晃甲板、打开多个界面、重新上/下船；观察是否发生穿模、道具丢失、场景水面错遮挡。记录 WebGPU shader 错误、黑屏和 GPU 帧时间。

## 自动验收与限制

- 新增 `npm run test:v48`：先执行 **18 项新船确定性检查**，再完整串行执行原工程 `test:v47` → `test:v45` → ... → `test:v39` 等回归套件，包含 21 项 GLB/哈希校验、角色/船状态机、多人通信逻辑测试。
- 离线 HTTP 启动：由 `start_v47.py` 的 `ThreadingHTTPServer` 提供资源；无需在线 npm 安装。
- **真实浏览器 GPU 验收未成功**：该运行环境的 Chromium 自动化访问 `http://127.0.0.1:5173/` 返回 `net::ERR_BLOCKED_BY_ADMINISTRATOR`，不能声称已经在 Chrome/Edge 中完成 30 分钟游玩、60FPS 测试或材质/海水遮挡视觉验收。
- **重要未完成：** 真正的逐三角 swept-capsule CCD、船内海水完整 stencil/depth 排除、多个真实隔舱的独立水位、全部骨骼动作精修、面片级幕布/索具物理、多人场景全部可携带物品的网络权威复制、真实设备验证。V48 提供实际可执行的原有玩法 + 重点修复，而不是声称修复了全部 3A 问题。
- 当前船壳和运动学仍沿用 V44 与 V47 的保守水线近似；新的甲板与碰撞代理更准确，但不等于在 Blender 逐面重拓扑后的完整船壳碰撞。
