# Tidewater V33-A：陆地交互、村民行为与后续逐项质量门槛

> 交付性质：**可运行的第一阶段修复包**，不是 3A 美术终版，也不是全部陆地联机功能完成。完整保留 V32 海岛、海上/深渊驾驶与战斗，改动集中在陆地。

## 1. 根据玩家截图审查出的根因

| 问题 | 可核对根因 | V33-A 处理 | 验收情况 |
| --- | --- | --- | --- |

| 机关按 E 没提示、互相抢键 | 不同对象直接读取同一按键且部分被剧情阶段提前过滤 | 告示牌、石碑、三面镜、村民统一候选列表；优先级与距离确定焦点，只消费一次 E | 键盘仲裁、阶段无效提示自动化测试通过 |

## 2. 玩家立即可试的功能

1. Windows 双击前先解压完整 ZIP；在游戏项目根目录执行 `python start_v33.py`。首次如需 npm 依赖，原启动器会按已有流程处理。
2. 步行到林中石碑附近，用可见的三级台阶从正面进入，碰到中央石碑不能直接穿过，靠近按 `E` 读取铭文。
3. 接取港口告示牌任务，走到灯塔调查，再去三面镜前逐次按 `E` 旋转。**未到剧情阶段时 E 会提示下一步**；不能假装镜片已经解锁。
4. 靠近有姓名的居民按 `E`，出现四个选项（三种话题加离开）。`1`~`4` 或鼠标点击可选择，`Esc` 结束。结束后点击游戏画面可再次锁定视角。
5. 驶回海上，V30 的潜艇车钟、鼠标自由观察、上浮下潜、武器及深渊怪物应保持原控制；V33 没有重写这些模块。

**当前 10 名村民**：阿岚、米拉、洛恩、塔娅、艾文、霍克、莉亚、赛恩、诺拉、凯伊。他们的对话为**本地预设选项**，不是实时大模型自由聊天；目前很多人复用 Joe/Marta 外观，不能声称已经制作了十套独立模型。

## 3. 操作键归属和联机预留

| 场景 | 输入 | 所有权规则 |
| --- | --- | --- |
| 陆地无弹窗 | E | 候选交互目标按优先级、距离决定唯一响应；已有船舶/特殊模式交互提示优先 |
| 陆地战斗 | Z / 左键或 J / K / Q / 右键 | 拔刀/轻击/重击/闪避/格挡，依旧受冷却与体力约束 |
| 步行 | V | 第一/第三人称镜头；不改潜艇 V 的视角 |
| 村民对话打开 | 1–4 / Esc | 对话框独占输入并冻结角色攻击输入；关闭后恢复 |
| 海上与深渊 | 原有 W/S、A/D、Space、Ctrl | 沿用 V30 车钟驾驶；陆地更新不接管 |

联机的正确后续边界：玩家 `actorId/sequence/tick`、输入动作事件、互动对象 ID、对话或机关事件应成为可回放意图。**客户端不能声称伤害、奖励、机关完成**；由现有服务器扩充场景身份、距离、CD、场景存档与事件去重校验，再广播权威状态。**本版只保留接口方向，不宣称已实现多人陆战或同步机关。**

## 4. 真正可用的外部模型/动作来源与筛选原则

| 候选 | 许可证与实际状态 | 采用方向 | 需要补的技术工作 |
| --- | --- | --- | --- |
| [Microsoft Rocketbox](https://github.com/microsoft/Microsoft-Rocketbox) | MIT；本包已有 Joe/Marta，各有 80/81 关节、7 个真实 talk/idle/wave 片段；上游还有其他人物及数百动作 | **最优先**：较自然的村民与船长 | 从上游实际下载 FBX/动作，Blender 重定向统一骨架，导出自包含 GLB，定位脚底，再逐动作实测 |
| [Quaternius Universal Animation Library](https://quaternius.com/packs/universalanimationlibrary.html) | 旧通用动作包 CC0；**未打包** | 步行、跑步、翻滚、剑击 | 并非与 Rocketbox 直接通用；须重定向骨架、足底锁定并确认每个动作授权 |
| [KayKit Adventurers](https://github.com/KayKit-Game-Assets/KayKit-Character-Pack-Adventures-1.0) | CC0；**未打包** | 可独立制作统一的风格化外观方案 | 风格偏 low-poly，与当前接近写实人物混用会更违和；只作备选，不默认替换 |
| [Khronos glTF Fox](https://github.com/KhronosGroup/glTF-Sample-Assets/tree/main/Models/Fox) | 逐文件核查，示例狐狸带 CC BY 4.0 模型/动画署名；**未打包** | 狐狸待机与移动 | 模型尺寸、落地、方向、动画切换、许可证署名及自带材质兼容性 |
| [Poly Haven](https://polyhaven.com/license) | CC0；**未打包** | 灯塔石材/铜氧化/潮湿墙面 PBR | 分层贴图、光照和 LOD；避免一次性引入大量纹理使浏览器卡顿 |

重要：一个素材网站有“免费下载”并不代表任何图都可重新分发。使用前必须同时记录作者、原链接、许可证、下载日期、修改与 SHA-256，再检测 GLB 是否带蒙皮、动画以及外部依赖。

## 5. 逐角色逐动作验收，不粉饰缺失项

执行：`python tools/audit_land_v33.py`。每行列出人物和每个必要动作（A：文件中实际有此片段；F：程序退化补偿；-：缺失）。

执行：`python tools/audit_land_v33.py --strict`。**本交付包预期不通过严格美术验收**，原因是 10 位村民未全部拥有不同的模型，Rocketbox 缺完整 walk/run/attack/hit/death，动物怪物为旧临时网格。这是有意保留的真实阻塞信息。

如要替换某一位居民：

```text
python tools/install_land_assets_v32.py --import-glb resident_fisher C:/models/fisher.glb --license CC-BY-4.0 --attribution "作者、作品名、来源地址"
python tools/audit_land_v33.py
```

每个角色的额外**人工画面关卡**：

1. A/Tpose 检查身材比例、模型原点、脚底高度；标准站姿脚底不得入地。
2. Idle → walk → run → idle：原地切换不得滑脚，需观察双脚支撑相与上坡地形。
3. Combat：动作帧与服务器判定窗一致；挥刀要有接触点、受击/格挡反馈和死亡清理；对动物不套用人形动作。
4. Dialogue：走近时头部朝向、招手、谈话姿势、选项点击和离开恢复控制。
5. 压测：10 个居民、动物、敌人同时进入视野，测试 30/60/144Hz；检查远距剔除、纹理驻留与显卡内存。

## 7. 这一次实际运行的检查及剩余风险

- `npm run test:v33`：通过，包含 V33 新碰撞/交互/A* 验收、V32 陆地战斗与模型结构测试，以及 V31→V11 海洋回归链。
- `npm run build`：通过，Vite 成功编译 285 个模块。
- 已独立使用 Blender 观察内置 Joe/Marta 的网格最低点约为本地坐标 -1m，并在加载路径抬高到脚底对齐；**仍需 Windows 浏览器实际检查肤色/装备/足底**。
- 本执行环境的 Chromium 无法正常建立无头浏览器 socket；独立远程浏览器又无法访问本机 127.0.0.1。**因此不声称 WebGPU 实机画面通过，也不把自动化逻辑测试当成美术完成检验。**

## 8. 运行与回归

```text
python start_v33.py
npm run test:v33
npm run build
python tools/audit_land_v33.py
python tools/audit_land_v33.py --strict
```

最后一个严格美术命令当前预期返回非零，这代表**剩余工作被明确检测出来**，不是工程无法运行。
