## 2. 《盗贼之海》可借鉴的机制，不复制其知识产权

### 2.1 操船的多任务压力

- 在单个连通的空间里，玩家能看到并走到真实的舵、帆索、舷炮、船锚、货舱、维修点。
- 风向改变有效帆力；海浪改变视线和炮角，不能只是缩放海面贴图。
- 战斗节奏来自取炮弹—装填—瞄准—开火—后坐—维修—舀水—泼水之间的取舍。每一项必须真实消耗资源并可取消。
- 检验使用“无 HUD 数值也能看明白”原则：帆角改变、绞盘回转、炮弹进膛、钉板定点覆盖破口均有世界空间结果。

### 2.2 幽灵舰队与场景分层

Sea of Thieves 官方 Haunted Shores 将幽灵舰与不同炮弹、漂浮战利品、移动舰队一起设计，不是单独复制一批绿船：
https://www.seaofthieves.com/haunted-shores

设计采用 **远景可见威胁—中景舰队机动—近景实体交战** 三个尺度：
- 1.8km：海平线云墙和不正常的蓝绿夜光；禁止成堆模型先出现。
- 1.1km：舰队分支、破帆形状、间歇鬼火，舰队成员最多三组、各自有阵位。
- 550m：真实炮弹和受击；首领舰控制增援，普通舰遭受伤害后修正战斗队形。
- 击沉后：不凭空消失；先开裂、绿雾散解，再生成世界实体战利品，库存不可重复结算。

### 2.3 风暴要有远近层次和玩法后果

- 远程：完整云墙/天色变化，云隙闪电间歇出现；海上能从晴区观察风暴。
- 边缘：阵风、低能见度、雨、船帆受力异常，海面先出现白浪。
- 深处：大幅升高海况/船体横摇、能见度急剧下降、甲板打滑、炮弹瞄准困难、船舱有条件进雨水。
- 中心：以逃生可操作性为约束限制吸力；允许操帆逃逸，不强制锁死键位。
- 高性能约束：不实时改变 FFT 频谱相位；动态过渡位移幅度/泡沫/天气场，避免巨浪瞬跳。

本项目设计借鉴《盗贼之海》的多机制反馈与美术方向，不能复制 Rare 的独家模型/动画/声音/UI/商标。

## 4. 目标美术规范：复古海盗世界与鬼火舰

- 木材：冷暖对比；主色烟熏胡桃木，抛光铜件与锈蚀铁带；板缝、风化破损、锚链、甲板铆钉独立建模；不做大面积随机拉伸贴图。
- 单块甲板/舷板连接必须在转角处按共同边缘拼接；反向法线、背面透明、Z-fighting 都是阻断性缺陷。
- 主船必须具备连续**外壳—室内骨架—舱板—艉楼—楼梯—货物点**，不能把实景壳体与不可进入的旧壳体叠放。
- 鬼船采用深青色半透明冷底色，碎帆边缘绿色发光，内部骨架与舷炮鬼火，船尾浓雾。透明排序与深度遮挡要稳定，不能纯 alpha 把整艘船变成一个穿透的塑料盒。
- 龙卷采用厚云口+窄腰+海面水雾支脚，上下连续；视觉位置跟随同一物理中心。当前 V45 已有连续曲面，但缺少 3D 体积噪声、内层旋涡、浮沫/雨雾阴影、环境照明响应。
- 天气具有“可从安全海域观察到危险海域”的大范围对比，在不同区域停留 60s 时都应有看得见的风、浪、雨、天空变化。

## 5. 正式船体：不能继续非等比拉伸旧船

**目标船体**（作为新 HeroShip 独立原型，不代表已实现）：约 22–25m 长，5–7m 宽；完整上甲板、侧舷炮位、船长区域、中层甲板与船底货舱；楼梯不是贴图，也不能用单键闪现代替。

1. `VisualShipRoot`：只负责编队可见模型、帆骨骼、炮窗、损坏和舱内灯。
2. `PhysicsShipRoot`：基于新船水线轮廓重新分布的浮力采样、质量/惯量、力矩和航速，不可沿用 8m 船的固定采样。所有空间以同一个 `ShipLocalFrame`（1单位=1m）转换。
3. `CollisionShipRoot`：独立的船壳/舱壁/甲板/楼梯碰撞，通道必须通过 capsule 半径=0.3m、角色高约 1.75m 的真实检验。
4. `InteriorShipRoot`：上中下层连续过渡、房门、爬梯、照明、通风口、破口与局部真实水位。
5. `WorldItem`：从世界物体 → 左/右手 socket → 容器 slot → 甲板/货舱落地物 → 拾回，ID 稳定；禁止出现“拿起来只是隐藏模型”式实现。
6. `InputActionRouter`：所有动作一次消费，具有 UI / WALK / DECK / STATION / CLIMB / CARRY / COMBAT 六种互斥上下文。每一次 E 按下有明确目标、可见距离和执行后反馈。

**几何验收阈值**（设计要求，非当前测试结果）：走行通道宽 ≥0.85m、净空 ≥1.85m；上中层坡梯有同尺寸台阶/扶手碰撞；零透视漏缝；静态角落前后 360° 摄像机不穿舱壁；连续 30min 人/箱移动无失踪、穿底、抖动。

## 6. 远洋世界重排：危险不能堆在港口或同一个坐标

现有文件 `src/offshore/OffshoreField.js` 使用港口中心 (69.8,36.5)。危害区以其远洋世界坐标为基准，程序中的天气始终连续。

| 区域 | 目标坐标/规划 | 关键玩法 |
|---|---|---|
| 港口安全海 | 以港口中心半径约 600m | 风小浪稳，学习操舵、装货、维修，无幽灵舰主动攻击 |
| 中程贸易航线 | (130,760) 一带 | 雨雾过渡、商船与小海盗随机巡逻 |
| 远洋风暴带 | (-800,2250) 一带 | 高海况、多重云墙、阵风、低光、低能见度和船体重心反馈 |
| 幽灵海域 | (-600,2450) 一带，**不同编队不共享同一个出生圆环** | V45 现有三个分散巡逻群，正式版再增加主动巡逻/舰队阶段与追击 |
| 水龙卷外围 | (-500,3570) 一带 | 随时间偏移的水龙卷中心，吸力带、旋转带、海浪和尾流交互 |
| 东部深海 | (970,1200) 一带 | 相对明亮但具有随机强阵风和特殊探索任务 |

**未来遭遇预算**：远景光学虚像不参与船体物理；中景 3–5 艘实体；近景 1–3 艘可以真正开炮和修复；动态抽样、帧率上下限和视距确保一张 L20/4090 也可顺畅查看（只作为性能预算，不宣称已测得 FPS）。

## 7. 阶段执行，不允许完成半套就标记成功

### P0（本轮 V45 已改，代码测试通过）

- 舱内渲染不再直接采样/绘制室外大洋水面，关闭水下 post；舱内仅显示 ShipDamage 进水。
- 补舱室墙板与顶板，舱内禁用外穿式第三人称相机。
- 修复 E 交互所有权、焦点按键残留、船舱物品跨楼层可误取、移动 dt 瞬断穿模。
- 天气驱动已有海面实际波高/泡沫，不再只是 UI 数字。
- 幽灵舰 3 个远洋分队，连续三维龙卷网格取代分层圆环。

### P1（未完成；首次导入实质复古模型）

- **先**取得 Poly Haven 或其他明确 CC0 高质量船 GLB，记录来源 SHA256 和许可；Blender 以真实尺寸拆件、裁剪、凸包/三角 Mesh 碰撞。
- 外壳替换采取 A/B 模式，外形每次只启用一套，禁止在原 8m 船 hull 上套叠 GLB。
- 完成连续 2–3 层船内空间及穿模检查；必须有真实楼梯和 6 个可通行障碍场景。

### P2（未完成；完整操作与人船）

- 单一的 ActionRouter + WorldItem，全套桶/水/炮弹/木板/灯/箱子/绳索可拿、用、放和回收，握持动画与世界物品同步。
- 水桶舀水→泼水，木板取出→走向洞→钉板；炮弹取出→放入炮膛→真实消耗。
- 角色 AI 在甲板/舱底之间走动执行维修和装弹任务，含障碍、岗位抢占及重算路径。

### P3（未完成；风暴/幽灵视觉完整版）

- 风暴区域天气一体化：云墙 GPU 动态云影、雨线方向、远景雷暴光、环境音、航行物理都来自同一天气场。
- 高品质水龙卷：3D 噪声/体积雾近似、巨浪与水雾支脚、船体吸力及逃逸机制一致。
- 幽灵舰模型真正取用 CC0 资产制作不同船型；海战编队切换、增援、船损、海面战利品。

### P4（未完成；验收）

每个功能必须依次通过：静态/单元测试 → 世界模拟 → WebGPU 浏览器交互 → 截图视检 → 连续 30–40min 实机 → 全工程打包安装 → 另一个浏览器复测。任何截图黑屏、舱内见外海、键位互斥、船体穿模均为失败，不靠测试数量冲抵。

## 9. 运行与增量修复

在包含 `package.json` 的工程根目录，安装 Node.js、依赖后使用 `npm install` 和 `npm run dev`；启动方式还可运行原项目内的 `python start_v44.py`。新的测试脚本：`npm run test:v45`。

如通过小补丁交付：解压 V45 补丁，在包含 `apply_v45_patch.py` 的文件夹里运行 `python apply_v45_patch.py "<原P2项目根目录>"`。会备份将要替换的每一个原始文件，拒绝没有 `package.json` 的目标目录。
