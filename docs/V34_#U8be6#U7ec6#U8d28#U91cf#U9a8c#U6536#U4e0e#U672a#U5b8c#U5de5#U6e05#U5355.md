## B. 逐项资源/动作审查的真实结果

运行 `python tools/audit_land_v33.py --strict` 目前不会通过，因为**缺少真正能重新分发的陆生动物、怪物 GLB 和每个角色所需的完整动画片段**；非严格模式只审核基础文件结构。

- **船长及 20 居民**：目前是项目内已随包分发的 `joe.glb` / `marta.glb`，为 MIT 授权 Microsoft Rocketbox 骨骼模型；每人有真实 idle/talk/wave，但 walk/run/attack/hit/death 是必要时程序过渡，**不是逐人真实动作捕捉**。
- **鹿、野猪、狐狸**：尚未集成可核验的授权 GLB；当前是原始程序占位造型，脚步只是四肢逻辑运动。不可标注为 3A 外观。
- **潮蚀兽、夜影猎犬、幽灵、灯塔守卫**：尚未集成真实角色包及配套 idle/walk/attack/hit/death 全套片段；现在只提供可玩的战斗逻辑和临时视觉模型。
- 角色审查共计 28 个槽位，82 项外观或动作验收尚未满足；`--strict` 应当保持失败，直到资产真正安装并逐角色审核。

## C. 核验过授权性质的公开来源

- Microsoft Rocketbox（MIT） 115 骨骼人物、417 兼容动画：<https://github.com/microsoft/Microsoft-Rocketbox>。
- Quaternius Universal Animation Library 1、2（CC0）：<https://quaternius.com/packs/universalanimationlibrary.html>、<https://quaternius.itch.io/universal-animation-library-2>，动作需重定向骨架并导出到独立 GLB 后才能导入自定义引擎。
- Khronos glTF Sample Fox（模型及动画注明 CC BY 4.0，三段 Survey/Walk/Run）：<https://github.com/KhronosGroup/glTF-Sample-Assets/tree/main/Models/Fox>。

**仅“链接公开”不等于“已下载”。**执行环境无法连接 GitHub 原始二进制下载 CDN，当前 V34 未打包这些外部素材。`python tools/install_land_assets_v32.py --import-glb ...` 可逐个导入本地获得且核验许可的 GLB；需要真实模型和片段全部通过严格门禁后才可正式宣称角色资产完成。

## D. 按键与模式隔离

| 模式 | 按键 | 行为 |
| --- | --- | --- |
| 步行状态 | E | 根据优先级只操作一个最近的门、碑、镜、居民或告示牌 |
| 陆地拔刀后 | 左键 / J，K，Q，右键，Z | 轻击、重击、闪避、格挡、收刀；同帧单次消费 |
| 步行时 | V / P | 第一/第三人称切换、冒险日志 |
| 居民面板 | 1–4、Enter、Esc | 对话选项、自由提问、退出；场景移动/战斗输入暂停 |
| 潜艇/船舶 | W/S，A/D，Space/Ctrl | 原海上车钟、船舵、上浮/下潜，陆地战斗不抢键 |

## E. 运行过的验证及保留的阻碍

1. `npm run test:v34`：V34→V11 一系列逻辑回归通过，包含 154 级阶梯支持点、跨阶连续性、真实门锁碰撞、20 NPC 日程、键冲突、受击去重、海战及联机协议。
2. `npm run build`：Vite 产物编译通过。
3. `npm run test:course`、`npm run test:harbor`、`npm run test:cottage`、`npm run test:pirate`：通过。
4. `npm test`：基础游戏逻辑先通过，但 `test/engine-smoke.mjs` 在当前 Linux 环境报 `No WebGPU adapter found`，不能说该项通过；浏览器/WebGPU 最终画面、碰撞手感仍需有 GPU 的实际机器检查。
5. `python tools/audit_land_v33.py --strict`：美术动作门禁**预期未通过**。此项不可跳过、不可将程序四肢摆动伪称授权独立动作。

## F. 不能虚报完成的剩余事项

- 导入 28 个角色槽位对应的合法独立模型或经批准可复用的外形，按物种核验骨骼权重、LOD、显存与 license，并在 GPU 中逐个看模；
- 对每个角色分别提供缺失的 idle/walk/run/talk/attack/hit/death 动画，并在多方向、起停、上下坡、攻击接触期间做足底与穿模测试；
- 用真实 WebGPU 机器走一遍灯塔上楼、门开关、石碑机关、30/60/144 帧视角、交互反馈、视觉气氛和战斗；
- 若要真正多人共享陆地任务，另行完成服务器权威位置/冷却/机关状态、断线重连和状态复制。当前只有协议预留，不能宣称服务器功能已实现。

项目目标是高品质课程展示；当前版本优先保障可玩的物理机制、兼容性和可审计性。以上“未完成”均为明确待办，不会通过改名或打包来掩盖。
