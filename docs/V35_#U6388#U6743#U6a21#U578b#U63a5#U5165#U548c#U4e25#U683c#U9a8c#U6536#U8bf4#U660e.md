# STORMWAKE V35 — 模型接入、逐动作审查与未解决问题

版本：V35。基于 V34 备份单独演进；继续使用项目原有自研 WebGPU/WGSL 引擎。

## 真实交付

- 正式接入并实际打包六种有骨骼与动画的动物/敌人模型，而非仅提供网址。动物和敌人初始化时从 public/models/land/manifest.json 加载；GLB 失败自动回退到旧造型，防止游戏整体瘫痪。
- 新增四个真人骨骼 NPC 岗位：巡林员、信使、学徒、夜间守卫。其余 16 个职位仍使用既有 MIT Rocketbox Joe/Marta；没有虚报为 20 套独立角色。
- 标准化动画动作表：支持模型自带 Gallop（逃跑）、Flying_Idle/Fast_Flying（幽灵）、Punch/Headbutt（攻击），以及由模型自带前缀包裹的 Idle/Walk/Run/Attack/HitReact/Death。动物可在静止时切换觅食、警觉与常态动作。
- 物理碰撞和战斗逻辑继续由 V34 接管，视觉骨骼不代替碰撞。保留既有 E 键交互优先级、Z/J/K/Q/右键和场景/联机意图日志。
- 附 Blender 4.3 渲染的离线接触表 LAND_V35_ASSET_CONTACT_SHEET.png，供模型品质与前后朝向复核。这不是游戏内实时截图。

## 本地质量检查

按“文件→骨骼→原生动作→引擎兼容→游戏回归”逐步检查：

1. 源文件：非空 GLB 2.0、文件长度校验、无外部贴图、无必须但不支持的 GPU 压缩扩展。
2. 骨骼绑定：每个资源存在 skin、16 根以上骨骼、独立动作、带 JOINTS_0 与 WEIGHTS_0 的三角形蒙皮网格，关节索引不越界。
3. 动作映射：用项目自身的 parseGLB 和 assignRigActions 对每一个可宣称的动作验证，而不是仅搜索名字。
4. GPU 成本：10 个已安装岗位的不同模型总约 4.47 MB 原始 GLB，具体验收数据见 test/stormwake-v35.mjs。
5. 离线视觉：由 Blender 导入资源观察比例、纹理、正反朝向；野猪增加 180° 朝向校正与 -0.24m 地面偏移；狼与鹿缩放到适合岛屿角色的尺寸。
6. 回归：npm run test:v35（包含 V34 至 V11）；npm run build；npm run test:course 均已执行通过。

## 严格门禁仍未通过——不视为最终 3A 验收

- **森林蟹依然是程序临时模型。** 发现的 CC0 蟹源资源被第三方转换成静态网格，不能伪装成完整骨骼动画。
- 主角当前仍使用更写实的 Microsoft Rocketbox 模型及部分程序骨骼补偿。备选的 CC0 角色动作虽然更齐全，但视觉预览是明显卡通风格，为避免画风倒退，未自动替换默认主角。
- 其他 16 名 NPC 的多样化衣装、完整走跑、面对面对话口型与表情尚未完成。
- 独立的实体视觉测试（WebGPU 浏览器内、显卡上）尚未执行；没有假称可达 3A 质量或全部碰撞动画一致。
- python tools/audit_land_v33.py --strict 将继续失败，这一门禁不会为了宣称完成而降低标准。

- 全量回归：npm run test:v35
- 编译：npm run build
- 美术门禁：python tools/audit_land_v33.py --strict（预期尚未通过）

代码仍使用 V34 陆地战斗/交互/服务器预留协议。游玩时 WebGPU 初始化或第三方贴图在具体浏览器出现异常，应以浏览器 Console、帧时间和场景录像为准修正。
