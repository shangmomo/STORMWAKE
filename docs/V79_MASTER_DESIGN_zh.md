# STORMWAKE V79—精品化总设计与工程实施规范

基线：用户提供的 V78 完整工程。设计日期 2026-11-26。下文【目标】均不是实装声明；实际交付以 `docs/V79_EXECUTION_zh.md` 和测试日志为准。旧 V63/V66/V70/V72/V76/V77/V78 文档保留，冲突时以本规范的验收规则为准。核心要求：真实可行走空间、可操作实体、相互作用的系统、完整游戏循环；禁止通过瞬移、假弹窗、无限资源、模型替换或跳过测试掩盖缺口。

## 1. 产品定位、世界与玩家循环

1–4 人合作海洋奇幻探索、复古帆船、深海潜艇、岛屿远征和巨兽狩猎；单人不是残缺版，多人不是观看房主。维持海风、潮湿木材、铜铁机械、沉船、深渊生物与岛屿自然地貌的统一艺术方向。现有自研 WebGPU/WGSL 引擎采用类似 Three.js 的 API，并非官方 Three.js+TSL。保留 V78 为可回退基线；若执行官方 Three.js+TSL 迁移，先在隔离分支建立海面、皮肤动画、阴影、深度后处理和资产兼容基准，再逐场景替换，不能凭技术名词宣布完成。

主循环：港口接委托→查图、买补给、装船→协作解缆起锚→依风向航行→遇险、调查/战斗/捕捞→实际获取和搬运资源→装船归港→验货、交付、修理、强化→新地区与更高风险。陆地循环：道路导航→休整→侦察→战斗或规避→调查与宝物→返航。深海循环：确认海况/压力→下潜→声呐与目视辨识→采样/探索→风险触发→撤离或击败巨兽→维修补给。任何循环都必须有失败后可继续的路径，不允许永久锁死任务。

设计目标：首十分钟能完成一次接单、补给与短程航行；一小时可完成一个有战斗/调查的完整闭环；不靠开发者命令推进。数值均为待平衡目标，沿用当前有实证的数值直至实机测量。世界时间联机由房间权威状态控制；睡觉不能单方面改变全房间天色。

## 2. 全系统一致的交互契约

每项交互必须具有 id、场景/楼层/载具坐标系、目标物、提示、可见性、距离/高度、遮挡、前置状态、输入拥有者、动作序列、提交点、取消条件、失败反馈、结算凭证、联网权限、验收用例。按键提示与可执行动作来自同一候选，不能看到 E 却触发另一个物品。

动作生命周期：Idle → Approach（玩家自行到达）→ Target（准星/方向/距离/可见性）→ Reserve（占用或锁定，若需要）→ Anticipation（转身、手伸向设备）→ Active（可碰撞/操作时间窗口）→ Commit（仅一次资源/世界状态写入）→ Recovery（收手、姿态恢复）→ Idle。Cancel 仅允许在明确阶段，释放岗位、手部、物品、相机和输入；Commit 后取消不撤销已完成结果，不能再次发奖。死亡、退出场景、断线、失去焦点、设备异常必须走释放路径。服务购买等瞬时动作可省略动画阶段，但不能省略校验与提交。

| 情境 | 输入与动作所有者 | 必须阻止 | 恢复 |
|---|---|---|---|
| 陆地探索 | WASD、跑、跳、E 场景交互、V 视角 | 隔墙/隔层读取、同时登船和接单 | 松键停止；地面稳定 |
| 甲板自由行动 | 真实船体局部坐标、E 岗位、Shift+E 下船 | 甲板与货舱重复候选；角色被船体甩出 | 同步速度继承，落水进入游泳 |
| 船舶岗位 | E 离岗，W/S 等由该岗位解释 | 移动、切武器、其他岗位触发 | 松键归零，离岗后输入清空 |
| 潜艇 | 舱内走路、站位操作、V 观察视角 | 外部相机绕过控制权限，双人占同岗 | 舱内安全位置；应急上浮 |
| 战斗 | 武器选择、攻击、闪避、格挡 | 同帧钓鱼/开菜单/拾取与攻击冲突 | 收招或受击打断，清理命中缓存 |
| UI | 菜单键与指针属于 UI | 角色移动、攻击、岗位残留命令 | 关闭后需新的物理按键 |
| 装载/失焦 | 停止输入；长帧不补跑无限步 | 旧按键重入、重复提交、半更新世界 | 重新获得焦点再按键；失败可重载 |

E 候选校验先检查有限坐标、楼层和范围，再查几何遮挡；门本身可被操作，但不能穿过闭门操作门后物品。候选冲突按模式、明确目标、优先级、距离与稳定 ID 裁定；一帧一个 E。手持货物优先放置/交付，空手优先瞄准对象。无效请求不给假成功音效；提示具体原因（离得太远、需要材料、被占用、战斗中、权限不足）。

## 3. 角色、相机、装备与动作施工规格

统一成人胶囊物理、脚底坐标、眼睛/头部/左右手/武器尖/盾面/背部/腰部 socket。角色世界位置为真值，模型与物理坐标单向派生；船内局部坐标以船世界变换转换，禁止混用世界和局部。静止呼吸、走、慢跑、冲刺、起跳、腾空、落地、上坡下坡、倒退、左右横移、转身、游泳/下潜/上浮、登船、爬梯、蹲伏（未来）、滑落、受击、格挡、闪避、死亡/复活均独立状态，动作切换有 0.08–0.2 秒混合目标。跑动由实际速度而非 W 键决定，脚底锁定在支撑面，不把墙面当台阶；落地时根据跌落高度控制受击，不在腾空时强制 IK。步幅与实际速度匹配，目标脚滑 <10cm/步、手握设备误差 <5cm（实机逐帧测量）。动作镜像须检查左右手约束；衣物/武器不能穿躯干、舱壁、地面；骨骼不拉伸作弊。第三人称相机有碰撞扫掠，收缩时不穿墙、回弹时阻尼；第一人称武器层仅在安全视角显示，正常场景仍需可见身体/正确第三人称。相机切换不能改变命中方向或船体操控权。

动作细则（时间为动画调校目标；已有短刃/长矛/钓竿的攻击数值见 PersonalWeapons.js，不能随意改动）：

| 动作 | 开始与准备 | 有效阶段/碰撞 | 收招、取消与反馈 |
|---|---|---|---|
| 走/跑/转身 | 输入向量、地面和体力，转身限速 | 胶囊扫掠、阶梯支撑、脚步节奏；上坡不穿地 | 松键减速；停止播放跑步；脚底对齐 |
| 跳/落地 | 地面且净空才起跳 | 初速与重力，顶棚扫掠；不在空中二段跳 | 接触稳定支撑后恢复；跌落提示 |
| 游泳/爬梯 | 水深触发/靠近梯子正面 | 浮力、梯级位置、双手交替；不能穿船壳 | 终点净空检查；堵塞停在安全端 |
| 拾取/携带/放下 | 空手/物品可达，预留重量 | 手 socket 与实体物品绑定，双手重物减速 | 放下须查地面及障碍；断线留物 |
| 开门 | 可达铰链/把手，预约动作 | 门扫掠体积对所有玩家/物品，转轴一致 | 关闭被挡时停/回开，显示阻塞原因 |
| 短刃轻/重斩 | 体力扣除、锁定方向、抬臂/跨步 | 真实刀刃扫掠，每目标每次最多一次，挡墙 | 收招不可无限取消；命中音、火花、受击 |
| 长矛轻/重刺 | 双手定位，前手滑动，后手发力 | 窄轴胶囊、尖端伸出实际距离，墙先命中 | 拔回、重击长硬直；无模型时不假装有刺击动画 |
| 钓竿战斗 | 抛钩预备，绳与钩独立 | 绳长/张力、钩实体飞行；体型、遮挡和绳承载限制 | 中钩小怪可拉近，巨兽只造成硬直/断线；取消回收 |
| 钓鱼 | 手持钓竿、合法水面、选择饵 | 抛物线落点、浮标、咬钩、拉力耐久、收线 | 成功入鱼舱或放生；满舱明确反馈，日志与结算一致 |
| 格挡/闪避 | 明确方向、耐力门槛 | 格挡角度与时间窗；闪避期间胶囊仍受物理限制 | 耗尽耐力破防；闪避终点不穿墙 |
| 受击/死亡 | 权威命中结算、关闭其他动作 | 受击方向、短暂硬直；死亡停攻击、释放岗位 | 显示死因，合法检查点复活；任务和货物按规则恢复 |
| 修理/舀水/锻造 | 真正工具、材料、目标破口 | 手与锤、桶或扳手对齐；长按进度；材料只在提交扣除 | 取消保留未消耗物，完成才更新损伤及外观 |
| 对话/交易 | NPC 可达且非战斗，正面对话 | 独立 UI 拦截动作；金额、货物、等级同步提交 | Esc/远离/死亡关闭；不可重扣、虚假成功 |

地下空间专项：用局部坐标/分区 BVH 管理真实封闭楼层，入口以连续道路连接；地表高度场不能覆盖地下楼板。地形可挖洞/遮罩必须与渲染、物理、水体统一。门宽目标 1.4m、走廊净宽 >=2m、成人净高 >=2.2m（结合实际胶囊半径复核）；升降机有上下呼叫、平台锁、双侧防坠、停层门、载重、断电应急；移动时玩家继承平台速度，绝不无碰撞穿层。路径回归每个方向/楼层 20 次，实际 WASD 不重置位置，故意撞墙、跳跃、蹭门、掉落及回退。禁止在地下未验证前直接移除地形碰撞或改为瞬移。

## 5. 复古幽灵帆船与真实航海

实体船体是世界空间刚体，甲板、货舱、船长室、瞭望台均为船局部空间的可行走网格。保留原 Dutch 船模、历史修复门洞和楼梯。实际接缝：梯口、船长室门、栏杆、舷梯、舱口、货舱货架、炮架、桅杆、绞盘和索具。门/舱口/绳索可以开闭；上层和下层各有独立候选与遮挡。船从停泊到航行：解缆（若有）→四把手摇绞盘收锚（多人贡献合并/对向抵消）→拉索展开主帆/前帆（实际布料、桁杆、绳端固定）→转舵→船速逐渐增加。风向改变帆形/横倾，船速不能由舵直接传送。主帆/前帆独立收放、理想迎风角、暴风缩帆和高风破损；桅杆与帆布连接、无断开的绳索。放锚须检测海底深度、链长和船动量；水面浪高、船体浮力和视效一致。船体之间采用连续碰撞接触和有限冲量，搁浅不瞬时弹飞；船只及乘员共享相对速度和伤害。单人 AI 可操作未被占用岗位，优先救急，不争玩家位置。

火炮流程：搬弹→插入→推弹→装填完成→转炮/抬炮→发射→后坐→清膛。炮口与发射速度同一实际模型坐标系；炮弹有限，空炮不能发射；炮击船体产生定位破口、甲板火灾/进水、水桶排水、木板修补；货物重量、进水与船体吃水相连，沉船货物浮起或沉底，玩家落水而非被传送。四人抢同弹药/岗位/木板必须只有一个成功，断线物资落在可取位置。

## 6. 魔鲸号实体潜艇与多人分工

当前 V66–V78 已有局部舱内空间、控制台、四岗位、共享战斗基础；不是完整外壳与内舱统一结构。目标：停靠母船或浮航→外甲板到舱口→打开气密盖→真实梯子→前室关闭外门→确认压力→内门开启→走入舱内。两门互锁，水下外门禁止打开，紧急脱险需上浮或逃生装置。外壳、门洞、梯子和内舱尺寸必须按原始 GLB 米制配准，不能只隐藏外壳伪造空间。现有前驾驶舱、中武器/声呐、后工程舱布局保留，实测净空、操作者眼高、窗位置与海水遮挡；窗户透过真实外部海洋，但碰撞仍封闭。

| 岗位 | 操作链 | 共享依赖与反馈 |
|---|---|---|
| 驾驶 | 入座 E → W/S 推进、A/D 转向、上浮/下潜 → 制动 → E 离岗 | 舵回中、压力/深度/推进功率，松键后按阻尼停；声呐提供方位；工程故障限制推进 |
| 武器 | 走到台→领取弹药/装填→瞄准、锁定→发射→观察命中/冷却 | 鱼雷、磁轨鱼叉、深弹各有实体弹道；声呐目标标记，弹药守恒；不能穿船体发射 |
| 声呐 | 开台→扫描→发现回波→标注深度、方位、可信度→反声波 | 扫描消耗电力并产生噪声；巨兽可能被吸引；反声波窗口清楚显示 |
| 工程 | 查看分舱图→领取零件→走到破口→工具维修→关隔舱/排水 | 分舱积水导致配重、氧气、电力变化；应急灯与泵互斥资源预算；不能按 Y 凭空满血 |

工程系统目标：前/中/后三个分舱分别有完整度、进水、氧气、压力、供电；受击位置决定破口，不只是全局 HP。隔舱门关断后进水传播停止，打开时按水位差有限流动；泵速随电力、压力和故障变化；维修件必须真实搬运，修补期间需要持续在场，工程师受伤/离开可中断。上浮减压、低功率航行、紧急灯、应急浮力预留能量；断电后保留手动门和有限照明，确保没有永久软锁。单人可让 AI 接管空岗位或停船换岗；多人四个岗位互相产生有效贡献。科研潜艇与魔鲸号保持独立任务、设备、升级和权限，不混用舱位/按键/资产。所有新机制上线前在独立模拟器验证守恒，再接渲染，再四人实机。

## 7. 怪物、海洋与陆地生态

生态不是视觉摆件。区块以世界坐标和深度生成有限种群，种群有巡游、警戒、逃离、捕食、恢复；捕捞后逐渐恢复，不在视线内重刷。浅海小鱼、珊瑚、海草；岩礁蟹与底栖生物；峡谷鳐鱼、掠食者；深渊低密度发光生物与巨兽。生物大小、材质、动画与水流方向统一。鱼群采用实例化和分层 LOD；可交互实体近处升级为独立状态，远处仍保留数量/资源变化。水下声场、浮游颗粒与深度衰减；深海不能只是提高亮度，照明应来自潜艇和生物。

普通敌人与 Boss 通用状态：巡逻→感知→追击→选招→蓄力→实际有效碰撞→收招→重定位→疲劳/阶段转换→死亡/脱离。目标依据距离、噪声、视线、仇恨和可达性选择。招式锁定点/方向在蓄力时确定，阶段变化不突然瞬移。敌人攻击必须有实际骨骼动作、预警、接触形状、命中反馈、恢复窗口；特效范围与伤害范围一致；场景墙壁/海底阻挡或限定攻击。Boss 不在窄门堵死玩家，卡住后找合法路径，不能无限穿地/瞬移到玩家身边。失去目标恢复区域初始状态（不重复发放奖励）。

利维坦：现有冲撞、撕咬、水炮、声压、漩涡及 V66 七种元素技能。冲撞蓄力收鳍、固定轨迹、掠过后掉头；撕咬口腔/下颌真实骨骼、短时间接触；水炮定向射流，先有压力预警；声压按球壳而非全地图；漩涡有切向流、向心吸引和逃脱窗口。霜晶、雷裂、热泉、新星、电牢、寒冠、热液的三维预警体积与物理命中形状一致，沿用 V66 初始数值直到实机平衡；每招需有颜色外的几何与声音提示，低画质也不能消失。70%/30% 阶段变化先退出当前攻击再转换，增加组合而非纯粹膨胀数值。四人联动：驾驶规避，声呐识别并标记弱点，武器找窗口发射，工程修破口；单人允许暂停换岗或 AI 补位但不免伤。巨兽接触船体需真实局部命中，不凭距离扣全船血量。三首魇龙与终章利维坦保持不同战斗身份和解锁关系。

陆地熊、狼、暴龙、翼龙、荒潮船长、Lurker：四足的脚接触坡面、转弯半径与步频一致，飞行动物遵循高度范围；荒潮船长专属横移、格挡、刺击、冲刺、收招；暴龙尾巴和头部使用分段扫掠，口部与伤害对应；Lurker 优先修复原资产蒙皮/动作再使用，缺失时标记阻塞而不是新增低质怪物。受击、死亡、掉落与角色行动具有同一权威结算；死后不再攻击。战利品为独立实体，可拾取、搬运、装舱、交易。

## 8. 任务、经济、保存与联机权威

旧有六条航程（金潮藏宝、失踪海图师、风暴航标、破帆商船、幽灯之夜、深渊回声）保留，陆地灯塔→东部远征→深层岩心→北部调查→化石谷狩猎及地下世界分支接入统一任务图。每条任务以真实事件推进，不用点击 UI 改写进度。schema：questId/version/prerequisites/stages/objective/target/guards/action/commit/receipt/failure/retry/optional/rewards/authority/localization。状态 Offer→Accepted→Travel→Objective→Return→Claimable→Completed；失败 Failed→Retry/Abandon，已交付事件不回滚成可领奖；材料与货物有唯一 ID。任务地图标注下一合法目标与可选路线；地图/日志/世界不各自维护一份真值。任务失败明确原因与可重试条件，禁止因掉货、断线或升级后永远无法进行。

奖励必须只写一次，钱包余额、奖励回执同一记录原子提交；旧任务进度与钱包分离时使用可重试待发放记录，不能先把进度设为完成然后谎称金币到账。普通交易也要检查有限金额、非负库存、真实物品拥有权；存储失败撤回变更，提示玩家；无持久存储允许明确的临时会话，不宣传为永久保存。货物守恒：世界+手持+货舱+已消耗/出售的数量总和保持；死亡、断线、装卸、沉没、重新加入均要测试。保留旧两种货币/存档兼容，未来统一必须有迁移表和回退，不擅自清空存档。现阶段不得让客户端自行提交任意伤害、金币、升级等级、任务完成或材料数量。

联网设计：服务器维护房间、演员/载具、岗位租约、物品、事件、奖励；20Hz 固定模拟 tick 作为初始目标，客户端发送有单调序号的 intent，服务端校验身份、模式、距离、遮挡、权限、冷却、材料与速率，再应用、发 ACK 和快照。远端渲染插值，驾驶/人物预测和纠正仅用于视觉，服务端最终裁决。连接断开立即撤掉危险命令/超时释放岗位，货物安全落地，重连恢复服务器已提交状态；房主迁移不回滚已结算，不重复领奖。V78 的魔鲸号仍有房主模拟、服务端边界校验，不能冒充专用服务器权威。先用回放测试再逐系统迁移，不让已有 LAN 流程突然失效。

## 9. 视觉、美术、声音与性能

资源导入门槛：来源/作者/许可/原文件哈希/面数/纹理/骨骼/clip/比例/单位/轴向/pivot/碰撞/LOD/使用场景。检查原始 UV 与贴图，法线与粗糙度/金属度材质色彩空间一致；玻璃、帆布、透明叶片做深度/排序专项；灯火有实体来源，局部光限制数量。美术优先保留高质量资产、以合法简化工具制作 LOD，不接入来源不明的替代品。V76 岛树 LOD0 约160万面不得直接铺满世界；酒馆与铁匠许可仍待核实，未经确认不可公开再分发。动作资产必须具备真实骨骼与 clip、验证重定向后才进主工程。需要新增模型但无法合法获取时列阻塞，不虚构许可。

渲染分级：近景原模、距离 LOD、远处实例/代理、不可见剔除；大型 GLB 分段解析、纹理/几何上传预算、缓存共享、失败超时、销毁释放；必须先构建碰撞和渲染再原子启用可交互场景。已进入建筑不得因视距切换丢失碰撞。不要在每帧生成大型数组/三角网格；物理采用空间分区和有限步进。参考固定步进的上限与插值策略，不能给当前强耦合 GPU/输入循环直接套完整固定步长而重复提交 GPU 命令；先剥离纯物理模拟再迁移。使用真实墙钟帧间隔报告 fps/长帧，不能用截断后的模拟 dt 冒充性能。

目标（待测）：1080p 常规画质 60 FPS，1% low >=45 FPS，场景加载不卡死；测试港口、船上、风暴、潜艇、巨兽特效、森林、酒馆、洞穴各自 10 分钟，记录真实 p50/p95/p99 帧时、内存、GPU 错误、加载耗时、峰值与长时间增长。低档保留碰撞、关键预警、可见目标与任务信息；高档只增加非玩法视觉细节。不能为提高帧率删除关键物理或动作。

音频：室外风浪、室内木材回声、洞穴混响、下潜低通、艇壳受压/泵/发动机、脚步材质、武器命中/格挡、怪物蓄力、任务完成各自独立，距离/遮挡与场景绑定；警报优先级高于音乐，切场景淡入淡出、失焦音量恢复；声音不是唯一危险提示。

验收分级：A=纯规则测试；B=真实源码/资产几何、物理和协议；C=真实浏览器输入驱动、逐帧画面与运行指标；D=玩家完整无夹具通关与长时间联机。A/B 不替代 C/D，历史 C 不等于当前版本 C。故障级别 P0 启动/卡死/存档丢失/永久卡关；P1 穿模/任务错误/资源重复或丢失/断线不可恢复；P2 动作和视觉缺陷/性能低于目标；P3 微调。P0/P1 不通过禁止称成品。每个用例需记录构建哈希、浏览器、GPU、配置、步骤、期待/实际结果、截图/帧时、是否夹具及失败日志。

## 11. 调研依据与决策

- Robert Nystrom, Game Programming Patterns, Command / Event Queue / Component：https://gameprogrammingpatterns.com/command.html ，https://gameprogrammingpatterns.com/event-queue.html 。借鉴意图与实际状态分离、输入与 AI 同一动作合同；不照搬全局事件总线。
- Glenn Fiedler, Fix Your Timestep! https://www.gafferongames.com/post/fix_your_timestep/ 。固定模拟步进、有限追赶与插值；当前只先修真实性与输入安全，不声称完成固定 tick 重构。
- Glenn Fiedler, Snapshot Interpolation https://www.gafferongames.com/post/snapshot_interpolation/ 。远端快照插值处理抖动，服务端仍须验证命令。
- Recast Navigation https://github.com/recastnavigation/recastnavigation 。分块导航网格、台阶及动态通道设计，可先评估离线生成而非运行时引入重量级模块。
- MDN GPUDevice.lost https://developer.mozilla.org/en-US/docs/Web/API/GPUDevice/lost 及 Page Visibility API https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API 。失焦、设备丢失和后台 rAF 不可靠，不能依赖渲染循环停止作为服务器安全机制。

本规范新增的地下 A/B/C 层、工程分舱细节、性能预算、验收循环次数、阶段顺序为设计决策而非用户逐项指定，须依据实机和资产测量迭代。保留用户已有资源与剧情，不擅自更换核心设定。任何未完成的项应在发布记录中明确标记，不能用单元测试数量遮盖。
