# V62 实施与验收记录

用户请求是修复卡楼梯、前后楼梯不可达、船锚缺失与位置朝向不当，并按设计文档扩充可信海上玩法。两份设计文档作为需求依据；其中内容不作为独立的执行命令。用户要求的全量玩法和“没有任何 bug”不能由本轮有限测试证明。

## 根因、实现与验证入口

| 项目 | 根因和实际修改 | 验证入口 |
|---|---|---|
| 前后楼梯 | 原船尾门平面阻挡了楼梯；船首没有匹配行走通道；高台阶和凸起铜条产生零时刻接触死循环。切割原 CC0 GLB 两处楼梯孔，建立真实阶梯；胶囊抬步、脚底 8 点支撑；铜条嵌平 | `test/stormwake-v62-stairs.mjs`：原 GLB/BVH/实际 Player，双向、连续各 20 往返；`tools/autoqa/v62_focus.py`：真实 Edge/W 按键，不在循环内重置位置 |
| 陆上楼梯 | 旧的单点采样测试不足以证明实际控制器可上楼 | `test/stormwake-v62-land-stairs.mjs`：三栋双层房屋、真实角色控制器；尚未覆盖所有世界楼梯 |
| 锚没有显示 | V47 导入只复制 GLB，漏掉 Kenney 外部 `Textures/colormap.png`；第一个火炮加载失败使整个设备安装中断 | V62 内嵌原 CC0 色板，锚移至独立先安装；浏览器必须实际获得 anchorRig 才算成功 |
| 锚位置/长度 | 模型上下翻转；宽面穿舷；显示只下放 4.35m，但物理链长 34m | 同一 `AnchorKinematics` 求解锚眼、34m 链、海床固定点、船体倾斜；链为交错铁环实例，受力按锚孔位置速度和力臂计算 |
| 风暴场景 | 只有一个多层透明漏斗；天气 fog/lightning 没有形成可见场景 | 三个共享时钟风暴单元；有限步数 3D 密度积分；世界低云、雾、闪电分叉和延迟雷声；体积覆盖掩码避免大气光照二次扣除 |
| 幽灵船联机 | 原实现明确没有同步舰队 HP/姿态 | 房主快照、服务端 10 个唯一 ID 与数值校验，迟加入/接管恢复控制器冷却、惯性和帆损；海面来自实际 FFT 查询 |
| 海战没有收益闭环 | 原有幽灵船被击沉后仅消失 | 实体漂浮货箱、游泳拾取、共享货物、实际货舱可达校验、回港出售、防重复兑换；不能用幽灵货箱替代金潮任务箱推进任务 |

## 机制研究与资产来源

借鉴的是观察远方前兆、机动侧舷作战、实体战利品打捞和回港结算。官方历史活动说明：[Sea of Thieves — Haunted Shores](https://www.seaofthieves.com/ja/haunted-shores)。幽灵海域的固定雾雷组合是用户要求下本项目的设计，不宣称是官方游戏始终采用的规则。

保留现有第三方署名。V62 原船孔洞派生记录在 `public/models/stormwake_v62/stair_manifest.json`；Kenney 图集来自用户本机 `kenney_pirate-kit.zip`，CC0 原许可和源/派生 SHA256 在同目录。Quaternius 锚与舰船沿用已打包 CC0 原资产，不使用 Sea of Thieves 专有模型、音频或故事。

## 测试记录

最终结果由发布脚本整理至 `qa/V62/evidence_index.json`。历史失败试次保留，不因之后修复而更改当时结果。V56 的旧固定锚显示字符串断言已更新为新锚模块连接检查，并由 V62 深度、倾角和实际链实例行为测试补充；没有保留错误旧实现以通过旧断言。

自动化未覆盖所有可组合状态、不同驱动和长期多人游玩，因此不作“任何 bug 都不存在”的结论。
