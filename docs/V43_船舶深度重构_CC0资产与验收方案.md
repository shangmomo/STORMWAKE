# STORMWAKE V43：可游玩海盗船系统深度重构与 CC0 资产执行方案

调研日期：2026-11-13。检查基线：用户上传 `STORMWAKE_V42_FullSource_DeepGameplay.zip`，包含 777 个 ZIP 条目。本文件是**资产调研与源代码审查方案**，不是已经集成、运行或实机通过的 V43 游戏版本。

## 0. 设计定位

- **保留**自研 WebGPU/WGSL、海面、天空、渲染管线，不迁移 Unity/UE。
- 借鉴《盗贼之海》的**功能深度与多人协作节奏**，不复制其模型、贴图、动画、音频、UI、商标和专有代码。
- 首先打磨一艘可真正游玩的 1–4 人小型海盗船。优先实现 *船体空间—设备操作—物品拿取—人船协调—损伤—海战—任务* 统一闭环；以后再扩展多种船型。
- 任何模型资源都必须来源清楚、允许修改和随游戏再分发，记录到 CREDITS.md 和资产清单；模型存在并不等于功能已完成。

## 1. V42 已定位的结构缺口（源码审查，不是浏览器实机测试）

| 文件 | 直接观察 | 对实际游玩的影响 |
|---|---|---|
| `src/ship/CrewAI.js` | 固定 3 个 actor 对应 `helm`,`sail_main`,`cannon_starboard`，只向站点写入输入，缺少船员移动、寻路、任务抢占/中断、受伤和物品搬运 | 船员像固定设备，不是活跃伙伴 |
| `src/ship/CrewVisuals.js` | 人物 holder 固定挂在对应船体局部站点；是否可见由岗位占用决定 | 玩家看不到船员走到炮位、跑到舱底修船或搬运 |
| `src/ship/ShipStations.js` | 舵、帆、炮、锚主要靠标量和状态位，炮用 `loaded`/`cooldown=2.8`/`reloadQueued`，未见炮弹库存的扣除 | 炮械机械手感和资源约束不完整 |
| `src/ship/ShipDamage.js` | 全船单个 `integrity/breach/fire/water/sunk`，无局部命中点、破口实体和舱室化积水 | 炮弹命中不同部位没有空间反馈；修船更像加血 |
| `src/ship/EnemyShotgunBoat.js` | 敌船直接更新 x/z/yaw 和 HP 等逻辑值，未采用与玩家同一套浮力/操帆/撞击/破口模拟 | 海战可能表现为敌船“滑行”和抽象数值伤害 |
| `src/world/boat/FleetVariants.js` | 多种外形复用单个 8.2m 船体物理主体；船外观大量程序化几何生成 | 同一套固定站点适配不同船形困难，多层可行走船舱缺乏空间 |
| `src/voyage/VoyageDefs.js` | 主航程只有 `voyage_gold_moss_01` | 重复玩法内容少，海战和任务难形成长期循环 |
| `src/ship/PirateHands.js` | 手和道具为程序化几何与相机姿态联动 | 尚不能实现高质量手部 IK、真实抓取接触和双手持炮弹等 |
| `src/engine/loaders/GLTF.js` | 支持内嵌缓冲的 GLB 和基础骨骼动画，但不支持外部缓冲、Draco、meshopt、sparse accessor 和 morph target | 新动画和人物需预先用 Blender 转为兼容 GLB；不得假设任何 glTF 都能直接加载 |

现有 `public/models/land/` 已含约 26 个 GLB，包括海盗角色；`public/models/characters/` 已有 MIT Rocketbox 人物；`CREDITS.md` 已记录 Quaternius 来源陆地角色和 Poly Haven 道具（包含木桶、水桶、鱼刀、木箱等）。这些应先复用或评估后替换，不重复下载。

### B. 暂不作为主线

- Quaternius Ships Pack (https://quaternius.com/packs/ships.html)：CC0 但主要是 6 艘简单船型。适合外观替换，不保证甲板空间、碰撞、舱底及可操纵装置。
- OpenGameArt 的 Pirate Ship (https://opengameart.org/content/pirate-ship-0)：作者明确标注**模型不完整、未贴图、可能存在法线/网格问题**，不要作为主力可玩船身。
- Pirate Cove – BlockImagine (https://1camou.itch.io/pirate-cove-blockimagine)：2026-10 新发布，标注 31 件可动画 CC0 GLB/Blockbench，采用块状像素风、AI 辅助创作；未经独立 GLB 骨骼与质量检查前只作为候选，且整体画风与现有场景不一致。
- 任何 Sketchfab/Poly Pizza 的**单个**模型都需要核对单个商品页面许可证；不要把“可免费下载”误认为 CC0。

### C. 美术一致性约束

- 统一比例：1 glTF unit = 1m；引擎船体 local axes、角色模型 forward/up 统一；保留 manifest 记录补偿旋转及缩放。
- 统一颜色：木材温暖偏暗，铜件做粗糙边缘，高亮帆布/标识低饱和；让 Quaternius、Kenney 和自制内容共用 1 套 PBR 风格规范。
- 统一 GPU 成本：同类木箱和弹药实例化；同材质 mesh 可批处理；骨骼船员限制在活跃 LOD 与距离范围。
- 不保证原有 GLB loader 支持 Draco、meshopt、外部 bin、morph targets；所有正式资产走标准内嵌 .glb 转换和 loader 测试。

## 3. V43 唯一重点船型：可登船、可进舱、可战斗的小型海盗帆船

不再同时打磨六个皮肤。优先打造一艘空间足够、任务完整、操作准确的船；船壳视觉风格可以与《盗贼之海》不同，但功能必须完整。

### 分层船体结构（具体尺寸需随 V42 浮力/碰撞测试确定）

1. 甲板：舵、船钟、罗盘、主帆/前帆绞盘、锚绞盘、左右舷炮、炮弹箱、栏杆、登船梯、舱口。
2. 船长区：地图台、航程桌、望远镜/灯、日志、小型战利品展示架。
3. 中/下层：可行走的甲板下空间；木板/食物/炮弹库；货舱宝箱位；破口检测与积水视效；上下楼梯。
4. 艏/艉：可登船梯/绳梯、锚链与锚钩、船尾旗与救生浮具。
5. 单一真实 ship root：所有动态装置、碰撞体、船员与货物共享船体局部坐标；渲染层和物理层不同步时禁止以世界坐标临时修补。

**不可接受**：单个静态船 GLB 上贴可交互按钮，玩家无法走进船舱或拿起物品；用 UI 数值代替真实设备反馈。

## 4. 必须实现的功能闭环及具体验收

### 4.1 人物与相机

- 真实船体局部坐标系中的走、跑、蹲、跳、爬梯、持物、落水、重新登船；船体 pitch/roll/yaw 下脚底不离甲板。
- 第一/第三人称切换不改变玩家真实世界定位；镜头不钻入桅杆/船舱墙壁；炮位使用专用镜头。
- 动画状态：idle/walk/run/board/climb/work/repair/bucket/carry/sword/cannon/stagger；上下半身可分层，支持工具绑到 hand socket。
- **验收**：船高速转向且有海浪，船员可从尾甲板跑到船首、下船舱、再上甲板；全程不飘移不穿模。

### 4.2 舵、帆与锚

- 舵轮有实际旋转、限位、回中、速度影响、舵受损状态；船行进时转弯符合质量/水阻。
- 主帆与前帆分独立收放、转角、迎风效率；操帆时绳索、帆杆、帆布动作与航速一致；抛锚/起锚有玩家持续推动绞盘、速度、剩余行程和受损限制。
- **验收**：逆风错误调帆会慢；抬锚前推进不起作用；在海浪和空人岗位下帆量/舵角不神秘跳变；多人同拉绞盘可加速（未来可调）。

### 4.3 真正可拿取的船上物品

- 所有拾取目标统一 `WorldItem`：世界实体、可用状态、重量、体积、双手占用、承重移动限制、手持骨骼 socket、放下后船体局部坐标、碰撞、存档网络 ID。
- 水桶、炮弹、木板、宝箱、短刀、铲、灯、望远镜、指南针、食物有**不同**的使用动作、限制和中断反馈。
- 箱子可地上拾取、抱在胸前、放上甲板、装货舱、搬运上岸、出售；可被击落/坠海（至少进入拾回或漂浮状态，不得凭空丢失）。
- **验收**：A 放下一箱在甲板，船前进 50m，B 可正常拾取；断线重连之后货物没有复制或丢失。

### 4.4 水桶、破口、维修与火势

- 依据炮弹 hit point 建立 `HullHole`：`positionLocal`, `deck`, `radius`, `flowRate`, `repairProgress`, `state`；新伤口能在船内对应位置看到，并有水线声/粒子。
- 舱底积水是舱段数据，可把舱内视觉水位绑定实际容量。漏水速度取决于破口半径、破口的世界水线高度和船体姿态。
- 木板修补需要持板、靠近具体破口、连续敲打/固定时间、消耗数量，完成才将该破口转为 sealed；不能站在任意甲板位置恢复全船 HP。
- 水桶要完成：空桶→舱底舀水/海里取水→满桶→站舷边泼海/靠火源灭火→空桶；舀出量减少舱段积水，不能重复空桶泼水。
- 受损桅杆/舵轮/锚可成为局部设备故障；修复后恢复原功能。
- **验收**：打船左前舷出现左前舷洞；船体进水且舱底上升；修错位置无效；修好后流量停止但原有水不会自动消失，必须用桶排净。

### 4.5 火炮与海战

- 每门炮的机械状态：`IDLE→AIMING→LOADING→READY→FIRED→RECOIL→RESET`。持炮弹从箱中取、装膛、瞄准、发射，至少具备独立装弹时长与装弹动作；炮弹库存真实扣减。
- 弹种分普通实心弹、链弹（损坏桅杆/帆）、火焰弹（引燃）、散弹（近距离反登船，可 M2）；每种有不同轨迹/命中效果，M1 至少普通弹、链弹。
- 船内炮弹和修船木板库存有初始量、携带量与耗尽反馈；炮弹遵守发射速度、重力、炮口角、船自身速度与命中距离。
- 命中根据船体局部部位产生木屑/金属火花/水花/破洞/桅杆损坏；玩家站在甲板上可受击倒；玩家可被敌人登船，近战伤害有格挡/后摇/接触反馈。
- 敌人炮艇共享船舶航行/碰撞/受损原则，具备靠近、调角、侧舷开炮、换位、修船、撤退、搁浅避免；不能继续在水平面直接插值漂移。
- **验收**：从弹药箱只拿到 3 枚炮弹就最多发射 3 次；连续命中某处产生对应破口；水淹船舱时需要在开炮和抢修之间做选择；敌船有真实弹道和可躲避攻击；击沉掉落可回收货物。

### 4.6 船员是会工作的 AI，不是岗位摆件

- 角色实体始终在世界中，拥有局部位置、速度、朝向、手持物、背包、动画、当前 Job；工作状态变化不允许凭空消失/瞬移到岗位。
- 采用 `CrewJobBoard`：玩家命令优先、紧急修船/排水优先、平常操舵与调帆、战斗炮手、搬箱；工作包含领取、前往设备、执行、失败处理、归还空位。
- `MoveToDeckPoint` 使用船体局部导航点/连接图：deck fore, deck aft, stairs, hold, port cannon, starboard cannon；移动路径需检查船舱障碍。
- 模拟“跑到仓库拿板→下舱定位破口→拿板修补→舀水→跑上甲板泼水”的完整动作；资源不足时语音/文字汇报，不可静默成功。
- 玩家接管岗位，AI 先解除、离岗并去做另一项任务；多人联机以房主/服务端的命令与船员位置为权威。
- **验收**：单人玩家掌舵时 AI 会调帆、开炮或修船；玩家接炮时 AI 离开炮位，不占双重输入；船摇晃时所有船员仍在正确层级行走。

### 4.7 任务、装备与进度

- 告示板提供至少 3 种完整任务：寻宝并出售、商运补给与交货、追击并击沉 AI 海盗船（任务顺序可调）；所有任务支持中断、失败、重复领取和回港兑换。
- `VoyageDirector` 与货物、AI 敌船、经济系统统一校验，而不是 HUD 进度“看起来完成”。
- 海图可读目的地与船实时位置；出航指南引导“提锚→调帆→掌舵→离港”。
- **验收**：三条路线单人 + AI 可以完成；两人可合作；同一个箱子/敌人奖励不能重复领取。

## 6. 真正可执行的里程碑与验收顺序

### M0：资源兼容性核验
1. 逐一下载官方资源原包，检查许可证与可再分发条款，记录 SHA256 和来源 URL。
2. 从 Kenney 取 1 门炮、1 个箱、1 个船具；从 Quaternius/KayKit 取 1 个骨骼人物+idle/walk/work；离线转换成单 GLB。
3. 使用 `src/engine/loaders/GLTF.js` 和当前 skinning 运行一页资产预览；检查坐标轴、pivot、动画、骨骼、纹理和模型大小。
4. 在 `CREDITS.md` 写明新增来源、版本及授权。未下载的一律标为 pending。

### M1：唯一船体 + 人物空间
- 一艘可上/下甲板、可下船舱、碰撞和镜头正常、NPC 跟着船走；甲板不出现浮空/穿模。
- 测试用例：翻滚 ±10°、前进 50m、旋转一圈、上下楼梯、2 人持箱互传。

### M2：设备功能替代占位逻辑
- 舵、两帆、锚、炮、工具、箱子各有独立动画、状态与可见反馈；操作输入冲突全部隔离。
- 测试用例：无任务自由出海、起锚不中断、帆力方向变化、炮仅在 READY 开火、库存扣减一次。

### M3：可视化损伤与完整排险
- 局部破口、舱室水位、木板、桶舀水、泼海、火灾、桅杆断裂。
- 测试用例：局部 3 处命中，修 2 处仍进水；排水后保持干燥；资源耗尽得到拒绝反馈。

### M4：真实船员及敌船
- 3 名 AI 船员实际在甲板移动，执行多步任务；敌船采用船体动力学与真实炮弹命中。
- 测试用例：玩家抢岗、船员调度修船、敌船迂回/撤离/搁浅，击沉掉落。

### M5：任务完整性、联机与实机 QA
- 单机 + AI 三任务闭环、2 人同船、3–4 人并行岗位；服务端/房主验证物品与资源交易。
- Windows Chromium/Edge WebGPU 亲自运行 20–40 分钟：低帧率/窗口失焦/切换视角/断网重连/装置占用/死亡重生均需复现。

## 7. 工程规模与取舍规则

- V43 第一优先是“**一艘完整的船**”而非“一批好看的船”。其他五种变体先冻结新功能开发。
- 第一批必须能真正运行的项目：走动、舱底、水桶、维修、炮弹库存、炮弹碰撞、敌船、AI 修船、宝箱拿取。
- 音乐、复杂船饰、更多岛屿、稀有炮弹/海怪等可放到下一里程碑，避免再产生“系统很多但每个都只能演示”的情况。
- 不更换渲染内核；资产兼容由离线 Blender 转换解决，角色动画不兼容则替换该模型，而非临时改 `src/engine/**`。
