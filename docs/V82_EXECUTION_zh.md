# STORMWAKE V82 · 碰撞、互锁与场景安全发布

本轮以 V81 为基线，保留原始模型和所有旧文件。未迁移自研 WebGPU/WGSL 渲染引擎。目标是实际修复导致角色卡住、穿入墙体、交互抢占或整个模拟中断的共用底层缺陷，不将测试通过等同于美术实机验收。

## 已实施

1. **移动世界兼容**：`MovingSurfaceWorld` 加入统一 `query(AABB)` 接口，基于局部 BVH 与完整世界矩阵回传世界空间三角形，带保守球形粗筛。旧接口缺失会使幽灵舰/商船加入碰撞集合后，陆地 `combinedWorld.query` 抛出 `c.query is not a function`。同时补齐移动表面 `step` 与 `skin` 尺度转换。商船站立乘员按原局部点随新平移/旋转转换，隐藏或沉没时不再强制带动；幽灵舰隐藏时不再携带乘员。未宣称已经完成所有波浪与多人实机碰撞。
2. **角色上下运动**：陆地旧盒体、圆柱原本仅水平推出。新增垂直越界限制，在脚落地与头撞平台时先限制垂直位移，再进行水平碰撞；上台阶也验证净空。游泳转站立使用静态三角与盒体/圆柱胶囊检测，低顶不得直接转站立。原 F6 单机受限回退保留，未引入任意瞬移脱困。
3. **相机**：原中心射线无法覆盖圆柱或三角边缘，改为半径 0.10m 保守球体扫掠加盒体/圆柱膨胀射线；取首次接触而不是沿墙滑动后的末位置。甲板第三人称接入船体和动态门板，陆地/船舶距角色眼位小于0.65m自动采用第一人称呈现，隐藏会穿进相机的身体/手持货箱；退出遮挡后恢复。未完成真实 WebGPU 视觉检验。
4. **灯塔实体门**：运行态不再瞬间禁用碰撞，按源门轴和旋转角同步实体面板与碰撞；按最大0.035rad 的角步检查本地/远端步行游泳乘员，阻挡时停住直至清空。保留旧 `setDoorOpen` 接口供历史测试，实时游戏使用 `advanceDoor`。这是客户端门板防夹，不是全服务器门控迁移。
5. **交互冲突**：原始 Dutch 船的自动舷梯不再抢占 E 的普通动作；船上遮挡射线从角色眼位发出（非第三人称相机），考虑动态门。挖掘、海图师绞盘、幽灯绞盘、航标维修、商船维修的持续 E 绑定首次选中的候选 ID；只有持续按键、同一个动作仍在范围且当前所有权属于航程时才执行，菜单、离岗、切换候选、松键、新按键会取消旧动作。挖掘补齐明确的候选。原船尾梯及联机占岗待确认加入互斥控制状态，拒绝再占岗。尚未完全迁移所有历史交互系统到同一个服务器仲裁器。
6. **异步大模型**：酒馆、铁匠铺及岩石等 V76 建筑先构建完 BVH；本地/当前可见远端步行和游泳玩家胶囊若与待提交三角形重叠，则延后发布，清空后一次性同步发布视觉与碰撞。未加载区域不伪造碰撞，不主动将玩家传送出建筑。远端玩家长时间占住模型位置可能推迟发布，仍需多人实机测试。

## 设计决定

相机扫掠半径 0.10m、第一人称回退阈值 0.65m、门角步 0.035rad 与胶囊安全半径 0.34m 为工程安全初值，需真实场景验证。长按 E 丢失所有权后须重新按键，优先安全而不是无条件继续操作。无第三方新资产；既有授权问题未消除。
