# STORMWAKE V81 实施与验收记录

基线：V80 完整工程、V79 总设计及 V80 验收矩阵。保留原始资源，不引入新的第三方资产，不修改原模型授权状态。采用原自研 WebGPU/WGSL 引擎。本次实际施工如下。

## 施工内容
1. `MineLiftV81.js`：采掘站上下层差3.5m、0.85m/s实体木铁升降平台，双向呼叫、物理门、移动乘员支撑、14级备用楼梯。原角色控制器测试30/60/144Hz各7次完整上下层往返，备用梯20次往返，门互锁和空载呼叫专项通过。多人升降机暂禁用以避免未同步平台产生软锁，备用楼梯仍可用。上层调查增加80金币一次性回执；旧矿样任务仍保留。
2. 矿样工作台原坐标(345,-621)附近坡度阻挡步行交互，迁至(344.65,-616.9)，真实角色控制器走到交互距离且射线无遮挡，原干路保留。
3. `AbyssInterior`、`AbyssRoom`：舱内移动以0.08m子步扫掠，控制台和隔舱门边界参与斜向/快速运动碰撞，拒绝非有限输入。门状态由服务器直接裁决、广播，旧房主快照不能覆盖门状态；服务器门碰撞与客户端共用规则。四个真实WebSocket客户端验证门控、旧快照、阻挡和重新通过。艇体动力/损伤/任务等仍是房主权威，房主离线不支持迁移。远端船员使用既有 SailorBody 骨骼资源，异步加载失败保留旧简模，位置插值与离开清理有CPU测试，未完成真实画面与手脚贴合验收。
4. `FishStockV81.js`、`GameState`等：本地存档级分区鱼群，48m网格、24份、有效游戏时间每30秒恢复1份，满舱放生不扣预算；鱼竿使用咬钩位置、拖网用船位、蟹笼用部署点；局部鱼群密度与预算关联。存储失败时捕获结算完整回滚库存、日志、编号、鱼群及通知；非法物种/重量/坐标防护。并非全经济事务迁移，离线不恢复，恢复量在后续持久化时保存。多人仍非服务器共享鱼群。
5. `LocalWaterV81.js`、`Underwater.js`、`App.js`：局部椭圆水池和潜艇旋转坐标系矩形分舱积水，使用实际局部水位、介质边界和有限吸收路径，干舱不使用外海后处理，局部介质不显示海洋光柱。CPU测试覆盖平移/旋转潜艇、相邻干舱和独立水池。JS语法通过，新增WGSL渲染分支尚未在真实GPU编译和画面验收，属于发布阻断。
6. `LandRewardOutboxV79`：没有可持久化存储时不再假报保存成功，沿用原任务回执和补发重试。
