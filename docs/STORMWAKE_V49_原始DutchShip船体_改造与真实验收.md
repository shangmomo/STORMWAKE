# STORMWAKE V49｜原始 Dutch Ship 几何恢复与交互修复

版本：2026-11-14  
基线：用户上传的 V48 完整工程、原始 `dutch_ship_medium_4k.blend.zip`。  
定位：**恢复原船设计、降低穿模风险的真实源码改造版；不是已经通过显卡实机验证的零穿模完整版。**

## 1. 用户明确要求与本轮实现边界

此次修改不再以程序生成的船长室、叠加木地板或额外房屋代替下载的 Dutch Ship。所有可见的主船船壳、原船甲板、尾楼高台、桅杆、索具和帆布均从用户原始 `.blend` 制作。功能位置按照这些实测几何布置。

**必须明确的事实**：原始 Dutch Ship Medium 资产由静态 hull、rigging、sails 构成，**没有可直接使用的独立开关舱门、船长室内部几何、内壁、楼梯和全船室内碰撞网格**。因此本轮绝不保留 V48 虚构的“可开关船长室”和“可直接进入舱底”功能。这不是宣称已实现真正可进入船长室；若要实现，必须直接在原 `.blend` 的尾楼壳体里编辑门框、通道、舱室内壁和地板，再从 Blender 重新导出拆件，并单独搭建碰撞网格。

## 2. 实际文件修改

1. `public/models/stormwake_v47/dutch_ship_medium_pbr.glb`：直接从原始上传的 `.blend.zip` 重新导出；**不再裁掉 V47 刻意挖去的约 2×3 米甲板矩形**。三组原始网格和原始 PBR 材质仍在。模型 hash 写入同目录 `asset_manifest.json`。
2. `src/ship/HeritageDeck.js`：取消 V48 叠加的整片假地板、木盒船长室、屋顶、床、桌、木柜和假舱口；只保留四段位于真实船舷**外侧**的登船梯。新主甲板不再由独立可见“第二层木板”覆盖。
3. `src/ship/DutchHullWalkmap.js` 与 `DutchHullOuterProfile.js`：从原始三角形烘焙的采样表。玩家可行走高度按原船网格查询；船侧宽度随纵向船形变化。未找到源网格承托面时，不凭空生成可以站立的平面。
4. `src/player/Player.js`：角色在甲板上的脚底、登船终点、跨舷跳海和碰撞边界使用原船米制坐标；登梯采用阶段性攀爬而不是 E 瞬移。玩家与船刚体共用局部坐标。
5. `src/ship/StationSites.js` 和 `CrewNavigation.js`：舵位、炮位、帆索、维修点、物资箱和船员路径以真实原船甲板高度确定。
6. `src/ship/HeritageAssetRig.js`：关闭把整片原始帆布垂向压扁的临时动画，避免帆布与原索具交叉。保留基于 CC0 船具的必要交互模型，不再用程序生成的大量装饰性木架覆盖原船。
7. `src/voyage/VoyageM1.js` / `VoyageWorld.js`：船长室门、床、地图桌和伪造下舱口不再提供假交互；宝箱暂存在原船后甲板货位；维修、桶舀水改为当前可进入的甲板和船侧位置，避免因为关闭假舱而导致工具完全无效。船的受损状态、库存和火炮仍由原状态机管理。

## 3. 当前可用交互

- 舷侧靠近四处真实梯位：游泳时按 `W`/`Space` 开始攀爬（非 `E` 瞬移）；甲板跳过舷侧可落海。
- `E`：使用真实工作岗位，如舵、帆、锚、炮位、资源；`G`：放下携带物品。
- 炮弹/链弹要从弹药库存提取并装入炮膛；木板和水桶有持有与数量状态。
- 宝箱可搬上原船后甲板实际货位，避免从未开放的假船舱存放/取回。
- **船长室尚不可进入**，因为原始 `.blend` 本身未提供带洞口的室内结构；该项不是当前版本的已交付功能。

## 4. 测试与尚存风险

- `npm run test:v49`：V49 专项 10 项通过，随后运行从 V47 至 V39 等既有回归。静态校验覆盖原资源哈希、被裁甲板的恢复、四处梯位坐标、真实甲板站立高度、岗位坐标、模型缩放关系、靠梯攀爬、装备状态机。
- JavaScript 关键文件语法检查通过；GLB 解码及资源 SHA256 检查通过。
- **未通过完整产物编译验证**：当前环境 `node_modules` 缺少 Vite，运行 `npm run build` 提示 `vite: not found`。Windows 启动器使用 Python 本地服务器，用户无需 npm，但仍应在自己的浏览器验证 WebGPU 渲染。
- **无法宣称无穿模**：当前自动化 Chromium 不能访问 `localhost`，缺少真实 Windows GPU 下连续跑动、登船、海水遮挡与相机穿墙的视频或截图。尤其原船船壳的视觉材质和游戏内旧碰撞系统仍非完全等价，复杂俯仰、横摇、大炮后坐、船员动画、相机极端角度、海浪穿透原船甲板等还没有实机签字。本次不是 3A 完工验收。
- 静态 CC0 船壳没有可拆的炮窗门、完整内舱和逐物件动态碰撞。下一阶段要直接修改原 `.blend`，而非把别的房屋套在船上。

## 5. Windows 启动与手工验收

1. 完整解压单一 ZIP 包。双击 `START_STORMWAKE_V49.cmd`，或执行 `python start_v49.py`。
2. 在 Chrome/Edge 打开 `http://127.0.0.1:5173/?stormwake=1&heritageShip=1`。
3. 手工检查：在尾楼、两舷和船首站立，低角度检查原船甲板是否有重叠木板；从水里沿四梯攀爬；从船侧跳下；炮位取弹/装填/开炮；船体摇摆时角色脚底；相机朝船尾转动是否透视；无破口时海面不应透过甲板。
4. 若发现穿模，请保留发生位置、视角、录屏与浏览器 Console 报错，以原船几何的具体坐标修复。不应以单一 `clamp` 或新加一层木板遮盖。

## 6. 可信度分类

**已实施且自动验证**：原始未裁船模、无 V48 自建船长室/假甲板、来源几何采样、梯位和岗位坐标、既有逻辑回归。  
**部分实施、未真实 GPU 验收**：碰撞、人物和船协同、火炮视觉、船体与海面交界。  
**尚未完成**：原船模型内真正可进入的船长室、船舱、炮窗门、动态帆索，以及“所有情况下完全零穿模”的实机验收。
