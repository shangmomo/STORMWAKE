# STORMWAKE V32：陆地战斗、人物骨骼与合法美术资产

## 1. 设计目标与这一版的边界

V32 不另起游戏。它直接保留 V31 的海岛、密林、灯塔、三镜片解谜、潮蚀入侵、居民和海上内容，针对玩家反馈的“战斗按了没反应”“按键相互冲突”“所有生物外观简陋”补齐可验证的基础工程。唯一应当接受的美术方向是 **真实 GLB/PBR 网格 + 有名有根的骨骼 + 每种动作单独测试**。这是之后继续向 3A 美术品质发展的基础，而不是宣称现有程序球体就达到了 3A 品质。

这一版已落地：真实输入帧验证、战斗命中与 VFX、详细灯塔、第三人称船长、三位骨骼居民、带授权检查的动物/怪物 GLB 替换接口、程序骨骼过渡、可回放战斗事件。未完成：全部陆地怪物/动物的真人级定制模型、配套攻击/受击/死亡动作、复杂声画组合、权威服务器陆地同步。**没有已下载的第三方资产不会在文档里冒充已安装。**

## 2. 控制方案：每次按键只有一个当前所有者

| 场景 | 输入 | 当前行为 | 与旧快捷键关系 |
|---|---|---|---|
| 海岛陆地 | Z | 拔刀/收刀 | 不会打开海图；回到海上继续使用海图 |
| 已拔刀 | 鼠标左键/J | 轻击；无冷却时立刻释放 | J 在港口其他上下文仍是船坞 |
| 已拔刀 | K | 重击 | 此时不能再弹出小汐面板；未拔刀 K 仍可使用小汐 |
| 已拔刀 | Q | 翻滚闪避，消耗体力 | 其它上下文仍保持各自 Q 功能 |
| 已拔刀 | 按住右键 | 格挡（减伤与特效） | 游戏原有右键菜单禁止弹出 |
| 海岛陆地 | V | 角色第一/第三人称 | 驾船时 V 仍切换船舶镜头；深渊潜艇不受影响 |
| 海岛陆地 | P | 任务日志折叠 | **Shift+P** 打开拍照模式；P 不再误触拍照 |
| 海岛陆地 | E | 与告示板/镜片/居民交互 | 原有交互所有权逻辑保留 |
| 海上/潜艇 | W/S、A/D、Space/Ctrl 等 | 原 V30 船舶/深渊操控 | 陆地控制模块不截获 |

对话框、拍照模式等 UI 打开时，陆地角色不会进行隐形攻击；命中视线和距离均需满足验证。输入所有权代码在 `src/land/LandControls.js`，并在 `App.js` 的海钓系统更新之前运行。

## 5. 如何导入和逐动作检测

1. 确认 Python 3 安装，游戏目录执行：`python tools/install_land_assets_v32.py --download-open`。脚本逐个下载并检查来源与许可证；如网络限制不可达会输出 `SKIP`，不影响游戏正常启动。
2. 审查动画：`python tools/install_land_assets_v32.py --audit`。它输出每个角色的骨骼数、每个动作片段名字、idle/walk/run/attack/hit/death 的覆盖情况；未装素材或关键待机片段缺失时退出非零。
3. 手动导入例子（路径需自己替换为合法文件）：`python tools/install_land_assets_v32.py --import-glb warden C:/Downloads/warden.glb --license CC-BY-4.0 --attribution "作者，模型名称，网页链接"`。
4. 角色替换在运行游戏时生效；不能把不存在的动作当成已经通过。务必分别实测 idle→walk→run→attack→hit→death，查看脚掌落地、骨骼无扭曲、帧率、光照与着色。

当前实现有 11 个相互独立的替换槽：`captain`、`resident_harbor`、`resident_herbalist`、`resident_keeper`、`warden`、`hound`、`crab`、`wraith`、`fox`、`deer`、`boar`。海上生物不会被陆地资产意外覆盖。

## 6. 真实碰撞与战斗反馈

- 鼠标、键盘按下边沿只触发一次；连按遵循冷却和体力。
- 轻击 32、重击 58；重击攻击范围约 4.1 米，轻击约 3.15 米；需朝向目标，距离与高度有效。
- 命中生成**12 槽上限、4 种颜色分类**的网格粒子爆发（轻击青、重击蓝、格挡橙、受伤红），短暂显示受击环。粒子池是可复用的，不会因长时间战斗导致无限创建 3D 对象。
- 敌人拥有追踪/攻击预兆/蓄力/冲击/冷却状态。玩家闪避带短暂无敌时间，右键消耗体力并减伤；零生命回到镇上但保留关卡进度。
- 灯塔的墙体、门窗、灯室、风向标及管理小屋作为一个静态合并网格制作；门体目前仍是视觉对象（塔内尚未开发可漫游空间），不要把不可进入误称为已支持进塔。

## 7. 联机接口预留（不是宣称已经联机）

`makeLandActionEvent` 含 `version`、`actorId`、`sequence`、`tick`、`action`、`direction`，明确不允许客户端自行设置 `damage` / `reward`。`LandAdventure.onCombatAction` 是待连接的本地事件出口，`combatEventLog` 最多留 96 条。未来接入现有四人海战联机服务时：服务器验证场景、装备、耐力、技能 CD 与命中；复制动作状态给其他客户端并校准移动。当前版本**陆地仍是单机逻辑**，没有加入服务器权威血量和掉落，不能用这些预留字段假称已实现多人陆战。

## 8. 自动化验收与运行

```text
python start_v32.py
npm run test:v32
npm run build
```

V32 测试包括：真实键鼠事件输入，K 命中且 HP 扣血，原海上 Z/武器不受影响，命中 3D 光屑发射，角色 80 骨架程序过渡 quaternion 数学稳定，灯塔细节顶点数量、GLB 真实 skin+idle/talk/wave、恶意路径/未知许可证拒绝、联机动作包不容许本地声称伤害和奖励。`test:v32` 会串联所有已存在的 V31→V11 回归测试。**容器内 Chromium 的 WebGPU 可视化实机测试受系统 socket 限制，需在你的 Windows 浏览器实际打开复核画面。**
