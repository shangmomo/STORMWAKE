# STORMWAKE V44 P2 — 复古帆船、真实船舱、远洋风暴与幽灵舰队：完整执行与验收规范

版本：2026-11-14。基线：V43 完整源码 → V44 P1 → V44 P2。引擎继续使用自研 WebGPU/WGSL。

## 0. 验收准则：必须真正能玩

最终应能完成一次这样的真实旅程：在港口装载箱子、打开舱门进入可站立船舱、搬箱放在任意合法空间、上甲板起锚调帆、从近海驶出约 2 km 以上、遭遇区域天气骤变与巨浪、在绿色鬼火幽灵舰队中交战、从真实命中位置形成破口、AI 从仓库拿板材修船，玩家在舱底舀水并到舷边倒掉、穿过可吸船且可逃脱的龙卷区域，最后运回可打捞的战利品。上述每一步都要靠真实实体与状态变化完成，而不是 HUD 文字或瞬间传送。

美术学习《盗贼之海》的轮廓识别、风暴氛围、团队岗位与幽灵船的造型逻辑，但不得复制其模型、贴图、专有音效、角色和代码。只使用 CC0、原创或可确认授权商用和再分发的资源。

## 2. 复古船设计：结构必须先于特效

主船定位为 23–25m 的复古双桅木质贸易改装船，目标宽 5.8–6.4m，吃水 1.5–2.3m（物理校准后决定），深棕旧木、青铜锈蚀、暗红或灰白旧帆、磨损麻绳。视觉划分为：艏楼、艉楼、开放主甲板、可站立的中层炮甲板/货舱、局部低舱底、船长小室。23m 船不应为了“多层”堆出违反几何空间的三层宽大厅。

正式船内目标尺寸：主要通道净高 ≥2.05m、通行宽 ≥0.95m；双人会车宽 ≥1.45m；门洞 ≥0.90×2.0m；梯/楼梯宽 ≥0.85m，步高 ≤0.20m。所有楼层共用一套船体局部米制坐标，在横摇 ±15°、纵摇 ±10°、航行 50–2000m 时都能自由移动，手持宝箱能够沿梯上下，不发生胶囊碰撞穿模或视角穿墙。

甲板真实设备：轮舵、前后帆、升降绳/绞盘、可抛起的锚与链、钟、罗盘、航海图、左右舷火炮、炮弹箱、食物桶、维修木板、灯、舱口和双侧登船梯。中层：炮位后退空间、储物格、至少两条舱内导引路线、可交互门、维修点。下部：24 个小箱的真实放置空间、局部破洞、积水高度、舀水动作、货架与舱壁。

建模分离件：`hullStatic / deckFloors / bulwark / quarterdeck / cabinWalls / hatchPivot / ladder / sailsMain / sailsJib / boomPivots / helmPivot / anchorWinch / portCannons / starboardCannons / propsSockets / collisionProxies`。高面数 GLB 用于渲染，船体碰撞用独立凸体/走面，不能直接把整个船网格当动态刚体。

## 3. 免费模型：必须真正下载、验证、切件

首选候选：[Poly Haven — Dutch Ship Medium](https://polyhaven.com/a/dutch_ship_medium)。官方标 CC0，有 Blend、glTF/FBX 等版本、约 69k 三角形；官方写的 24.7m 是模型**高度**，不是船身长度。必须在 Blender 中检查真实长宽高、朝向、轴、船舱是否存在、索具是否分离、材质/纹理引用后，才能决定是否作为主船外观。该候选已核验许可与描述，但**本次没有取得并安装原始 GLB**。

配件：[Kenney Pirate Kit](https://kenney.nl/assets/pirate-kit)，官方 CC0、70 件，可作炮、桶、箱、码头杂物。人物：优先复用 V43 已携带的 Quaternius 海盗角色与原有资产清单；不同骨架必须在 Blender 离线重定向，不得直接用动画名假装模型已能播放。

统一导入管线：官方资源→许可证与原包 SHA256→Blender 确定 1m=1 Unit / +Y Up / +Z 前→分离可动部件并设 pivot→修补真正内部通道/楼梯→1K/2K PBR 纹理集与 LOD0/1/2→嵌入标准 GLB→通过 `src/engine/loaders/GLTF.js` 兼容检查→船根姿态与物理校准→实机 screenshot。Loader 现有缺少 Draco、meshopt、morph、sparse 等部分特性，禁止无转换直接投入生产。来源文件与授权信息记入 `CREDITS.md`、manifest；未取得资产一律 `pending`。

## 4. 真正可拿、可放、可存的世界实体

最终所有重要物品采用唯一的 `WorldItem` 数据：`id / type / kg / size / state / ownerId / shipId / localTransform / worldTransform / handSocket / collisionShape / saveVersion`。状态：`WORLD → PICKED → CARRIED → STOWED / PLACED → EQUIPPED / IN_USE → FLOATING / DESTROYED`。

拾取：第一人称视线、2m 距离、双手占用/重量与动画检查，箱子不能隔墙抓取。放置：表面存在、箱体无重叠、重心稳定、道路/舱门/梯口净空检查，失败保留手持状态并显示原因。存取：真实箱/桶/货架中物品 ID 从一个容器移动到另一个，库存扣减只有一个权威数据源。甲板与船舱物品存放在 **boat-local 米制坐标**，帆船前进 2 km 后仍在原处；掉海后应浮起或沉入海中，按规则可捞回。

专项验收：放 10 个宝箱、左右舷共发射 8 发、消耗 4 块维修木板、泼水 5 桶，回港存档再加载仍保持正确数量/位置；箱子堵梯口被阻止；两人抢同一物品只有一人成功；船沉后不会复制货物。

当前 `ShipStorageSpace` 只覆盖**任务宝箱**的水平空间检测、局部保存和舱口保护，不代表所有道具已统一。

## 5. 实体操纵、损伤与海战

帆采用相对风角与面积驱动的力：`F≈0.5ρ_air·Cd(angle)·A·V_rel²`，在桅杆受力点产生推力、横摇与偏航；主帆、前帆独立收放与角度。迎风错误必须变慢；视觉帆布收放和绳索收卷直接反映状态。舵轮具有真实转角、回中和损伤限制；锚有抛锚→放链→下锚→绞盘起锚→收锚过程，不允许按一下就立即对物理船产生不可解释的大位移。

每门炮 `EMPTY→LOADING→READY→FIRED→RECOIL→RESET`，炮弹必须从货架拿取，再装膛和点火；火炮位置在船体本地坐标，敌船及玩家炮弹有连续弹道/飞行时间/后坐/命中点。普通炮弹开局能造成真实局部破口；链弹打桅杆，火弹可以引火。受到命中的地方出现对应破洞与木屑，舱段水位按破口世界水线高度上升，板材封洞后剩余水量**不自动消失**，必须用水桶排出。

P2 已把新船炮弹命中从旧半径 3.25m 的中心圆替换为有姿态与长宽高的**扫掠船体盒**，船首和船尾不再天然免疫；大船破洞位置保留物理米制坐标。最终仍需更精确的部位盒/凸包和可见舱壁变化。

## 7. 动态天气：必须同时改变天空、海面、船与声音

统一天气场 `WeatherField(x,z,t)` 产出 `wind, gust, pressure, waveEnergy, swellDirection, rain, cloudDensity, lightning, fogDensity, visibility, current`，所有系统共享同一个天气状态，而不是云、雨、动力各自独立伪随机。

建议天气等级（**目标，不是当前实测**）：

|等级|风速|目标显著浪高|表现|
|---|---|---|---|
|晴朗|3–7m/s|0.2–0.6m|暖光、远景清晰、轻浪|
|降雨|6–12m/s|0.7–1.4m|铅灰云底、雨纹、海面变暗|
|大风|12–20m/s|1.5–3m|白浪、明显横摇和船尾波|
|暴风雷雨|20–30m/s|3–5m|闪电、低能见度、甲板水雾|
|龙卷核心|按半径变化|叠加局部环浪|涡流、拉力、强烈水雾|

最关键的后续工作不是简单增加雨粒，而是在 `OceanFFT/WaterSurface/BoatController.query` 之间加入统一的局部波谱/浪高变化，保证海面几何与船体浮力读到**同一组波浪**。暴雨不会穿过舱板到船舱内；雷声、船体吱嘎和风声根据真实环境改变；薄雾与闪电可在距离上衰减。

## 8. 水龙卷：有形体、有吸力、有逃生路线

生成 `FORMING→MATURE→WEAKENING→DISSIPATED`，云墙先出现，旋柱接近水面，与环浪接触；构成包括低云旋涡、环形泡沫、下端水雾、半透明螺旋体积层、落雷、风向飘散的水滴。当前 P1 有近似动态涡流力，P2 依然**没有**完整高质量体积云和环浪。

力学以径向吸力、切向环流和速度阻尼构成，有限力与角动量避免无限加速；对船舶施加平移力与转矩，还应影响甲板松散货物、船员移动和炮弹。玩家可以沿切线加速并在下风侧转出，不能强制中心必沉；单人+AI 必须具备可实现的逃生操作。

测试四条路线：距中心 800m 接近、400m 横切、100m 核心穿入、脱离后 1km。记录最高速度、角度、转向、被吸航程、货物位移与稳定性；不得忽然瞬移、翻覆次数失控或离开后仍被永久吸住。

## 9. 绿色幽灵舰队：不能只是一批发光箱体

美术语言：暗蓝绿 `#082D34` 的深色船芯，半透明幽绿 `#1C746C` 船壳轮廓，`#77F9BE` Fresnel 高光，鬼火 `#B6FFCD`；弯曲船肋、破洞舷侧、腐朽木头、撕裂残帆、断桅、链索与暗青薄雾必须有可辨层次。鬼火应沿桅杆和炮口不规则飘动，与海面反射、雨雾相互作用。远观有清晰老式船形，近观能透出船骨，不能全船都用一个亮绿色盒子材质。

10 艘目标编队：1 艘旗舰 `Hollow Flagship`（多阶段与重型幽炮），2 艘 `Drowned Brig` 护卫，7 艘 `Wisp Cutter` 游击舰。AI 状态：`FORMING→FORMATION→INVESTIGATE→FLANK→BROADSIDE→EVADE→RECOVER→SINK`，队形随风、玩家航向和其他舰受损变化。幽灵炮弹、水雷、火炮近身反馈都必须有实体弹道及可见伤害。击沉需播放帆布碎裂→魂火散逸→壳体消融→掉落漂浮物的连续动画，不能瞬间 hidden。击沉奖励一个 id 只能生成一次并可回港出售。

远景可降帧运行 AI 和低面数 LOD，近景 3–5 艘完整物理/炮击，其余保持独立生命/状态并可受击。所有幽灵船状态最终需服务器权威复制。P2 的 10 艘仍是占位程序化模型，不符合这条最终视觉要求。

## 10. 船员、任务、联机

CrewJobBoard 管理 `STEER/TRIM/RELOAD/FIRE/FETCH_PLANK/PATCH/BAIL/DEFEND/CARRY/IDLE`，船员必须真正从存储架取板、走梯子、到具体破洞修理；资源不足/路堵/站位被玩家占用要反馈，不能瞬间移动。船体横摇、纵摇时角色保持正确脚底接触和分层 navmesh。1 人 + 3 AI 必须能通关，4 人多人模式要维护独立岗位占有和同一物品的唯一 ID。

至少 5 条完整任务闭环：出港与维修教学（港外过渡区）、东部商路运输（约1.5km）、外海幽灵舰悬赏（>2km）、龙卷挑战（约3.5km）、旗舰风暴最终战（>2km）。每条允许重复领取、失败/重试、回港兑换，奖励不可重复生成，存档/重连连续。

**当前验证**：P2 11 项专项检查、约 1800 帧静水刚体模拟、P1 与 V43 历史回归、源码语法检查；这些均不等于最终完成。WebGPU 实机操作与画面在当前执行环境未通过/无法验收。最终只有 M0–M8 全部通过，才有资格称作完全符合本规范的成品。
