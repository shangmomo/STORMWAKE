# STORMWAKE V41 · 船舶系统逐项修复与验收

构建基础：用户提供 `Tidewater_STORMWAKE_V40_QA_Repair_FullSource(2).zip`。目标是修好原有 WebGPU 项目中的船舶航行和船上岗位，而不是更换引擎或创建不相关样板。执行手册 `/docs/STORMWAKE_WebGPU_设计与制作执行手册.md` 为主要验收要求。

## 1. 故障定位与对应修复

| 设计 / 故障 | 源码问题 | V41 修改 | 验证边界 |
|---|---|---|---|
| 无航程时船动不了 | V40 的自动锚泊条件在 `aim` 为空时始终设置 `anchorDown = true` | 独立 `src/ship/AnchorPolicy.js`；有人登甲板后允许起锚；无任务自由航行，进目标港可以自动抛锚 | 真实 `BoatController` 平水面动力学回归，通过；实际 WebGPU 航行尚待浏览器验收 |
| 舵轮功能不完整 | 固定辅助动力 `.35`，玩家只能转舵 | `ShipStations.helmThrottle`，舵轮 `A/D` 转向，`W/S` 调节辅机，支持倒车；船体每帧接收输出 | 输入数值 / 物理积分通过；视觉驾驶手感尚需人工体验 |
| 船首锚绞盘无法自主控制 | E 操作会被自动靠港策略下一帧覆写 | E 切换起/抛锚，`anchorManual` 保持玩家选择，R 恢复自动控制 | 逻辑和重复边沿测试通过 |
| 炮位瞄准是假操作 | 生成炮弹时仅按船头角度固定射出 | `CannonBallistics.js` 舷侧弧与俯仰瞄准，默认略微抬高弹道，防止平视短距离入海；网络同步炮弹由房主生成 | 边界与 70m 弹道高度测试、真实双 WS 客户端通过；视觉命中率有待人工测试 |
| 联机控制不全 | 远程报文不含辅机轴和瞄准角 | `ShipNetBridge.js` / `coopHub.js` 校验和转发 `throttleAxis/aimYaw/aimPitch`，拒绝客机伪造炮弹广播 | WebSocket 双人测试和非法指令拒绝通过；多台真实浏览器仍待验证 |
| 岗位与船身姿态错位 | 船的 pitch/roll 变动时仅以 Yaw 投影定位交互位 | `StationSites.shipPoint` 使用完整的船体四元数；站岗人物高度取当前甲板碰撞高 | 姿态相关纯逻辑测试通过 |
| 岗位看起来全是假的 | 所有岗位用相同的程序化圆盘和标签 | 不同的舵盘/帆绞盘/锚绞盘/炮架/维修桶/水桶/货舱口；帆和锚指针读真实系统状态 | 几何结构可构建、JS 静态检查；画面品质和动作细节未人工验收 |
| AI 船员看不见 | AI 逻辑没有相应船上的人物根节点 | `CrewVisuals.js`，在船体局部坐标显示当前岗位 AI，优先复用包内 Rocketbox 人物，失败自动退回程序化模型 | 构建与逻辑检查；GLB 的实时载入和骨骼表现未浏览器验收 |
| 状态不明、操作不明 | HUD 缺完整航行 telemetry 和岗位操作 | 帆、舵角、锚、辅机、两侧炮弹装填状态；更新中英文操作说明和起航指示 | 代码审查 / DOM 结构静态检查；不同分辨率最终验收待人工完成 |

## 2. 验收层级

**A级：真实环境验证（当前未完成）**

- 在用户 Windows PC + WebGPU Edge / Chrome 中连续操作 30 分钟，检查 shader、船体漂浮、甲板碰撞、视角、开火命中和 AI 人物动画。
- 两台真实浏览器同一 LAN 操作左右不同岗位并观察 10 分钟延迟、断线、炮弹、经济结算。
- 4 人完整循环跑通：接航程—登船—升帆—出海—挖宝—搬箱—海战—回港卖出。

**B级：生产逻辑及资源验证（2026-11-13 已实际执行通过）**

- `npm run test:v41`: 新增 7 个船舶单元+物理模拟、专门的 WebSocket 炮弹与舵机同步测试，以及 V40 全套航程回归。
- `npm run test:v38`: V38 到历史 V11 的多代回归测试。
- `python tools/test_start_v38.py`: Python 服务器静态、JS 转换、HTML、内置 GLB/贴图与 UI 文件资源加载。
- `node --check`: 已检查 `src/` 与 `server/` 下 **298 个 JS 源文件**，0 语法错误。
- 原始 V40 ZIP 内 `src/engine`、`src/ocean`、`src/sky`、`src/post` **89 个文件逐个 SHA256 比对**，无变化。

**C级：离线物理回归（已通过，不代替浏览器游玩）**

- 用真正的 `BoatModel`、`BoatController`、`TerrainData`、`VoyageM1` 在固定水平水面输入中连续迭代 54 秒，无任务仍能移动约 **183.5m**，最高约 **3.57 m/s**（由模拟输入得出，不是实机测量值）。
- 互斥占岗、人工起锚优先级、A/D 和 W/S 输入分离、逆车、炮弹舷角和 70m 弹道、非法报文拦截。

## 3. 仍然存在的风险与下一轮手动检查

1. 当前执行容器的 Chromium 导航本地站点返回 `ERR_BLOCKED_BY_ADMINISTRATOR`，所以**没有完成可见 WebGPU 自动游玩测试**；绝不把代码层的 PASS 说成画面与手感完全通过。
2. 船员人物沿岗位站立、保留基本骨骼 idle 状态；尚未实现真实抓握绞盘、握舵和装填炮弹的手 IK，全新 AAA 动画不可声称已完成。
3. 风帆系统是手册规定的简化风帆力，不是真正全流体帆索模拟；靠岸碰撞、相对海浪状态在实际 GPU 海面必须复验。
4. 港口与藏宝地坐标继承 V40，灰苔岛仍是主岛的指定登陆区，不是全新的独立岛屿。
5. 当前房主权威机制已保护炮弹同步和货币事件，但未做公网 Relay 或玩家作弊全面防护，这是 M2 范围。
6. 默认没有重写利维坦、海盗主角、全岛地形及 Boss。现有入口保留但没有纳入本轮逐项浏览器验收。

## 4. Windows 最短人工验收脚本

1. 先关闭旧服务，双击 `START_STORMWAKE_V41.cmd`，在 Chrome/Edge 打开 `http://127.0.0.1:5173/?stormwake=1`，确认地图、角色、海面和航程 HUD 加载。
2. 不接任务直接从码头靠近船按 E 登甲板。检查锚状态从「抛锚」切换为「起锚」。靠近舵轮 E 进入，按 W/S 改变「辅机%」，A/D 改变「舵角%」，随后船位置应持续变化。
3. Esc 离开舵位，靠近主帆绞盘 E；W/S 改变「主帆%」，观察帆布缩放和船速变化。再切锚绞盘，E 抛锚、E 起锚、R 交回自动。
4. 分别操作左右舷炮，左右移动鼠标，LMB 开火，R 装填，检查不同方向弹道以及冷却和炮弹可见性。Repair 按住左键；船受损后应提高船体完整性。
5. 返港按 E 下船，在金潮告示板接任务，挖宝、搬箱、回港卖出；重玩一次验证不会卡死。AI 船员不能与真人同时占同一岗位。
6. 启动 `START_STORMWAKE_V41_COOP.cmd`，两台电脑各自启动本地页面，房主与队友一人舵一人帆，检查实际同船航行、同步炮弹和离线后岗位释放。
