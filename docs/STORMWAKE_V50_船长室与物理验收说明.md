# STORMWAKE V50 — 原始 Dutch Ship 上的船长室、海水空间遮挡、桅杆与物理验收

## 版本原则

- 继续使用 V49 保留的 Dutch Ship 原始船体、真实索具/帆，并且**只裁切**原甲板局部入舱口，绝不再叠加 V48 的假船长室、假屋顶、假长方形甲板。
- 船长室从本次上传的 TheMadraver 原始 `captains_quarters.glb` 改造；运行包保留修改后的完整模型、纹理和署名。原始未修改 GLB 仍由上传者持有，避免完整包内重复 27MB。这个模型原始长宽无法塞入 5.2m 船壳，因此按实际体量缩放到 x/z=0.37、y=0.58 后置于船尾高甲板下，来源/许可见 `public/models/stormwake_v50/CREDITS_V50.md`。
- 维持原版海岛、海怪、任务、舵帆锚火炮、物品、单机/联机逻辑。不得把纯表现的船当成第二套物理船。

## 重点位置数值（以船本地坐标、米计）

- 原船船壳约 21.96m × 5.20m；船长室原几何长/宽明显超过船体，无法无缩放整体嵌入。
- 经静态 walkmap 重新核对，真实**尾部高甲板**在 x≈0.17, z≈−7.43 处的行走高度约 1.93m；船长室地板约 −0.37m，入口垂向净距约 2.30m。
- Dutch hull 原始模型裁切矩形 x≈[-0.22,0.78]、z≈[-6.80,-5.90]（原 GLB 坐标，后映射到船本地）；对应 TheMadraver 屋顶裁切 x≈[1.45,3.45], z≈[-3.55,-1.15]（原 GLB 坐标）。
- 这两个开口不是各自任意放置；在新房间变换下投影重合。只有高甲板局部裁面，外舷、下层侧板和航海索具保持原状。
- 房间不能被解释为原 Dutch 船模自带室内结构；它是用户单独提供的**独立模型，经过尺寸匹配后装在船内**。

## 人物与物理：不要夸大

当前工程沿用自有 BoatController 船舶浮力/转向/力矩模型，而**不是**引入一个已独立测证的通用刚体物理框架。人物碰撞基于 sampled deck walkmap / capsule 与船本地障碍物的接触修正；高摇摆和快速旋转时仍可能存在边界穿透。所有舱内家具由模型原始 mesh bounds 烘焙，避免过去用一个任意大房间盒子掩盖问题。`MastLookout` 增加围栏约束。

WaterMaterial 使用新的 boatWorldToLocal 矩阵对海面片元进行保守体积裁剪，避免海面从舱内透出；它并非实时布尔网格/像素精度的完整船壳负体积。风暴巨浪和水反射仍应在真实 WebGPU 机器上测试，不保证对所有海况正确。

## 测试命令

`npm run test:v50`：先运行 V50 15 项资源/几何/舱室/水面/桅杆/船头专项检查，然后运行 V49 的原船基础测试以及 V47 及更早的 40 多个逻辑模块回归（输出会显示更多小项）。

`python start_v50.py --no-browser` 启动本地 HTTP；在同机 Chrome/Edge 打开 `http://127.0.0.1:5173/?stormwake=1&heritageShip=1`。

当前环境**没有安装完整 npm/Vite 构建依赖**，`npm run build` 无法执行（找不到 `vite`）；可启动的游戏使用原有 Python 入口提供 ES module 源码。由于没有获得本地浏览器 WebGPU 渲染的稳定访问权限，**没有经过 30 分钟实机 QA，不应称为零穿模/正式 3A 完工版**。

## 下次实机验收必须执行

1. Chrome / Edge 室内、船尾舱盖、两舷、船首，分别在静海与 ±12° 横摇下漫游，近距离截图确认无木板/天花挤入角色镜头。
2. 随船高转向速度 20 分钟，验证从岸边跳到不同原模型甲板三角形可落地、船边离船不会被锁死。
3. 船长室 E 看海图与 Z 地图一致，打开/关闭时指令不窜到舵帆火炮。
4. 破口前舱室无外海，破口后船舱内可正确展示局部真实舭水；当前版本没有验证完整多舱室进水视觉闭环。
5. W/S 实时爬桅杆，顶端能站立，爬升镜头和栏杆不穿桅杆及帆。
6. GPU WGSL 编译日志为零错误，1080p 实机帧率与内存消耗在目标预算内。
7. 联机中两名船员同时攀爬、开地图、下舱、开炮，验证状态同步与库存一致性。

如果某一条未通过，应记录复现路线、帧图、视角以及位置，修复后再重新签字，不能用通过离线断言替代真实游戏测试。
