# STORMWAKE：幽潮航海世界——《盗贼之海》式合作冒险新玩法与世界扩展总体设计规格

**版本**：新玩法 GDD + 技术设计 TDD v1.0｜2026-11-15  
**基线**：V58 自研 WebGPU / JavaScript 船舶与世界系统  
**定位**：1–4 人合作航海、海盗冒险、船舶操作、海岛探索、动态海战、深海巨兽  
**设计边界**：是下一阶段的**新设计**，并非声称 V58 已实现。文中角色、地图、任务、平衡和剧情为本方案原创提案；《盗贼之海》只作为体验机制研究对象，不拷贝其专有资产与叙事。

> 这份文档专门解决“以后应该建什么、每个动作怎么玩、不同系统如何相互作用、怎样做到真的可玩”。对 V58 既有 bug 的具体修复、测试链和源文件级补丁入口，详见第一份《现有工程深度修复与验收设计规格》。**新增内容依赖 V58→V60 的基础系统验收，不可抢跑。**

## 1. 体验愿景与独特性

### 1.1 一句话体验

四名海盗在一艘能够真实行走、工作、进水和沉没的古老帆船上出航，从风平浪静的海港进入不可预测的幽潮海域；每一次冒险都要求观察风、协同操作船具、决定是否冒险装载更多战利品，并在巨浪、幽灵船和真正接触船壳的海怪面前保住船与同伴。

### 1.2 借鉴什么，不复制什么

《盗贼之海》可借鉴的核心不是“卡通海盗皮肤”，而是：**船是移动的共同家园；操作是分工且可临时换岗；任务将玩家带向海域；海战不是拼血条而是打破口、修船、舀水；世界事件会打断计划；战利品必须带回港口，形成风险收益。**官方对 Voyages、Sea Combat 和 World Events 的描述支持这一系统结构 [S1–S3]。Wiki 对帆高/帆角、舵、绞盘和多岗位协作提供较明确的操作参考 [S4–S5]。

本项目保留差异：更强调**深海巨兽生态、风暴/旋涡/海难搜救、可深入探索的原船内舱和真实水下潜艇**。避免复刻现有游戏的岛屿、任务名、海盗 NPC、专有 UI 图标、音乐、地图或模型。

### 1.3 四项可验收设计支柱

| 支柱 | 玩家能直观做什么 | 设计上必须做到什么 |
|---|---|---|
| **动手驾船** | 真正起锚、拉帆、转舵、瞭望、装炮、排水 | 手与机关接触、状态连续、物理结果可见 |
| **同船协作** | 1–4 人即时换岗、一起起锚、救人、补洞 | 同一物理船/世界、同一物品/伤害、可重复联机验收 |
| **不可预测的航程** | 航海任务途中出现风暴、海盗、海怪、漂浮战利品 | 决策不是脚本强制；事件有前兆、区域/时间/难度门槛 |
| **可进入的世界** | 舱室可上下、岛屿建筑可进入、船头桅杆可到达 | 任何重要入口都走真实路径、不瞬移、不穿模 |

## 2. 产品范围、玩家人数与时间结构

默认以 **1–4 人同船合作 PVE** 为第一交付目标，保留日后 PVP/多船对抗扩展接口，但不能在主船物理尚不稳定时直接做开放世界多人竞技。建议基线为单船完整体验 + 可加入的 AI 船员；房间模式最多 4 真人，后加入、断线重连可恢复当前岗位与局部甲板位置。

| 体验阶段 | 用户时间目标（设计值） | 行为与教学 |
|---|---|---|
| 第一眼（0–2 min） | 2 分钟内理解视角、交互与出港目标 | 港口可见主船、可动船员、起锚和拉帆提示 |
| 首次起航（2–8 min） | 8 分钟内能独立离港 | 从绞盘起锚、拉帆、舵轮；可跳上船且不会掉穿 |
| 首次发现（8–15 min） | 获得一个地图线索或沉船求救 | 望远镜发现、船员协作确认、标地图 |
| 首次冲突（15–25 min） | 一次有意义的风险选择 | 驶过风暴以走捷径，或绕路、或打退幽灵炮艇 |
| 首次收获（25–35 min） | 可将实体战利品带回船舱 | 搬运、放置、库存/船载重变化 |
| 首次返港（35–45 min） | 完成卖出与船只修复 | 港口兑现、购买修船物资、选择第二次出航 |

**不能只靠提示文本“模拟”流程**。玩家在每个阶段都应执行至少一个需要视觉瞄准、真实位姿、按键持续输入或跨系统状态变化的动作。初期预制一个 35–45 分钟完整纵切片，比做十个没有完成终点的任务更有价值。

## 3. 游戏世界：海图、天气带与航海的选择成本

### 3.1 与现有 V58 地图衔接

继续使用 `OceanZones.js`、`OffshoreField.js` 所定义的空间区域。现有源码已经包括近岸商路、外海风暴走廊、幽焰舰队、龙卷海域、东部深蓝航线。新增设计采用**同一坐标体系**为已有区域添加任务入口、地标、敌对航线和天气边界，不要为了新玩法创建第二套互不一致的海图。用户已有主岛、港口、外围海域、巨兽、幽灵船和潜艇，必须在世界入口层保持连贯。

### 3.2 六类海域与可感知参数

| 海域 | 玩法作用 | 视觉/音频前兆 | 主要风险 | 奖励性质 |
|---|---|---|---|---|
| 潮汐港与主岛 | 新手、整备、交易、船坞 | 码头灯、海鸟、居民、晴天 | 极低 | 小额任务、基础装备 |
| 近岸航路 | 首航、捕鱼、基础藏宝 | 远方帆影、浅色海底、航标 | 小型礁石、天气变化 | 木材、食物、普通宝箱 |
| 沉船浅礁 | 甲板战、打捞、潜游 | 半露船桅、漂木、鸣笛 | 岩礁、掠食者、沉船结构 | 航海日志与零件 |
| 幽焰舰队区 | 船炮教学及多人海战 | 青绿灯火、鼓点、雾中船影 | 幽灵炮艇与登船袭击 | 稀有货箱和幽影晶核 |
| 风暴走廊 | 天气控制与船员协作 | 云墙、压低天空、迎面风切 | 抽帆、落雷、破帆、进水 | 高价值漂流货物 |
| 旋涡/深渊边缘 | 后期怪物、潜艇入口 | 海面旋线、深沉低频、鱼群逃散 | 漩涡、海怪、深水 | 古物与深海升级素材 |

### 3.3 世界事件调度器（不是随机刷一团光）

事件可以为 `sighting → warning → approaching → engaged → aftermath → cooloff`。输入来自区域危险度、航程类型、房间人数、当前船损、玩家近期遭遇、天气强度。限制玩家连续遭遇巨型威胁，尤其不能在首次 10 分钟出航自动刷终极 Boss。推荐事件预算：新手前 10 分钟无致命海怪；中期每 8–15 分钟最多一个主动大型威胁（此为待调优设计）；同一海域不得同时叠加超过一个巨兽与一个主舰队事件，除非明确是高难挑战。

**可预告的选择**：海盗看到风暴墙 400 m 外的变化，能决定绕路；不是到某坐标忽然被强制拖进战斗。所有天气与刷新共享服务器种子，保持联机一致。

## 4. 主船空间蓝图：真正能自由生活的 22 m 级原船

### 4.1 资产与形体原则

主船继续以已有 Poly Haven Dutch Ship Medium 的派生 GLB 为**视觉基准**，不因新玩法重新从零拼一艘低模方块船。现有约 22 m 船体的源码尺度需要再次在 Blender/GLB 导入阶段校验。每个活动点必须嵌在原船几何里：船长室、货舱、船头甲板、船尾甲板、船舷炮、桅杆、瞭望台、绞盘、航海图台、物资柜与小船/锚链接口，避免“后补建筑压住原舵轮”的历史问题。

### 4.2 五层空间连接拓扑

```text
   M2  ── 桅杆瞭望平台：望远镜、信号旗、索具观察
    │ Ladder M
   D1  ── 船尾高甲板：舵轮、罗盘、船长室外门
    │ Stern steps / original door
   D0  ── 主甲板：锚机、主帆索、前帆索、双舷炮、长枪架、鱼叉、水桶架
    │ Cargo hatch + real ladder         \ bow climb/rail
   H1  ── 下层货舱：货箱架、船板修理工具、水桶、灯具、储物区
    │ sealed access / bilge hatch
   H0  ── 舱底：排水、重心/进水、船体裂口与通路

   C0  ── 船长室（经原船尾门）：海图、日志、任务投票/航线规划
```

此图是**设计功能拓扑**，并非现有 GLB 已经拥有这些完全开通的楼层。实际施工前必须从原船剖面测量每处净高、梁柱、龙骨/桅杆挡位；若 22 m 船体容不下某个房间，就减少装饰/调整隔舱，而非压穿船壳或缩小角色体型。

### 4.3 四条不容妥协的路线

船头到船尾沿甲板自由行走；船尾外部与船长室双向通行；主甲板与真实下层货舱双向攀爬；甲板与瞭望台往返。每条都设计**正向+反向+携物+多人对向+风暴倾斜**五种场景。玩家站在船任何位置都应受船体运动驱动，不能出现船突然开走而角色悬浮。

### 4.4 船板、门和家具的细节

木板有可见接缝、钉帽、湿润边缘和不同磨损；栏杆高度合理且可以阻止误跌（玩家主动跳过则可落海）；门把/铰链独立骨架，能开门、关门、受阻停下；舱内桌椅在船晃动时不漂浮，物资柜打开后可见内容；航海图不是不可触碰的一张发光贴片，玩家靠近可互动、标记航点、俯视海图并同伴共享标记。家具物理要**先保证碰撞稳定，再增加可破坏细节**。

## 5. 可手动操作的航海设备（12 个标准）

以下表中的所有对象必须遵守 `可视模型 → 可达交互 → 权威状态 → 物理变化 → 动画/声音 → 多人同步 → QA 断言` 的七段完整链。

| 设备 | 角色站位与操作 | 动画/声音 | 可验证状态 |
|---|---|---|---|
| 绞盘/四把手 | 近距 E 抓把手，W/S 持续推，四人可并行 | 手掌贴木把、脚发力、齿轮/铁链声 | hands / turns / travel / tension |
| 船锚与铁链 | 绞盘控制，链下垂至海床 | 船锚实际进出水、链逐步收放 | anchor state / chain length / seabed contact |
| 舵轮 | E 抓握，A/D 或鼠标旋转，Esc 退出 | 双手抓轮、船舵声、轮心回正 | rudder angle / yaw rate / helm owner |
| 主帆长度索 | E，W/S 收放 | 绳圈运动、帆布卷放 | area ratio / traction |
| 主帆调整索 | A/D 改角 | 帆杆旋转、绳索绷紧 | sail yaw / wind alignment |
| 前帆 | 单独缆绳，可与主帆并行 | 布面绷紧、飘动 | jib ratio / wind force |
| 左舷炮 | 取弹→装弹→瞄准→开炮 | 抽弹、撞针、后坐、烟 | loaded / yaw / pitch / fire id |
| 右舷炮 | 独立操作 | 同左舷炮 | loaded / cooldown / damage |
| 船首鱼叉 | 抓握、瞄准、射出、拉回 | 钩索绷紧、缆轮拉紧 | latch target / length / rope tension |
| 地图台 | E 打开，拖动地图、点标记 | 镜头俯视、纸张动画 | waypoint list / teammate ack |
| 望远镜/桅杆 | 拿取、缩放、标记远处目标 | 手持姿态、镜筒移动 | spotted id / confidence / FOV |
| 修理站+水桶 | 拿木板/水桶→到破口/积水处 | 敲木板、舀水、倒水 | hole state / water volume / stock |

### 5.1 锚机微观操作场景

玩家跑到锚机时，靠近的把手出现单一高对比 E 提示；E 后角色移动到实际站位，手 IK 对齐旋转把手，双脚适当踩踏。按住 W，脚向前移动、把手产生扭矩，铁链卷绕；第二名水手加入后把手转速增加，但不是无摩擦的四倍；转过一个刻度有绞盘木头摩擦与链节声音。绞盘到顶时出现机械止动，人物松开并发生轻微反冲；锚先离海床，再通过海面，最后实际挂在船头锚座，船才能在风力推动下前进。

如果敌炮打坏绞盘，玩家拉不动，需要木板或铁件修理；当前损坏消息由服务器下发，全员看到相同断裂外观。若锚仍落在海床而帆全部展开，缆绳张紧、船头朝力方向偏转，可拖锚但不能穿透地形。

### 5.2 船舵与逆风操作

玩家把舵轮扭到某方向，动作明显但船的真实转向有惯性；风浪导致偏航，轻微纠舵更稳定。帆角不是纯外观属性：帆方向与风向对应产生正向推力或拖曳；逆风时速度降低，船不会无端靠隐藏引擎以恒定速度前进。多人协作允许一人掌舵、一人调整主帆、一人了望、另一人修船。

### 5.3 物理操作与便捷操作的平衡

追求**可信的动画与物理因果**，而不是把复杂帆船每根绳都做成按钮。主帆/前帆各提供 2 组真实关键绳（高度、方向），视觉上其他绳索可被动模拟；一人也能安全出航，四人协作可以更快、更稳定。可选易用模式提供长按加速和提示，但不绕开必须存在的状态机与物理反馈。

## 6. 人物控制、手部交互、身体碰撞与动作系统

### 6.1 人物基础姿态规范

一个可玩海盗需要 Idle、Walk、Run、Sprint、Jump、Fall、Land、Crouch、Swim、Climb、Steer、Capstan、SailPull、CannonLoad、CannonAim、Fire、Carry、Repair、Bail、SwordStrike、Hit、Death 与 Recover 等至少 20 组动作/混合状态。不是要求每一组都昂贵动捕，而是要求**动作阶段、脚部接触、装备接口、击中时刻和转场**全有数据。单人第一人称使用双手/工具可见，第三人称与远端角色需要全身动作。

### 6.2 真实手部逻辑

手部目标点是模型骨骼/设备上的 socket，模型动时 socket 随动；例如抓转盘时手的位置每帧依赖转盘角度，而不是播放固定空气挥舞动画。左/右手分别约束，贴近时可采用手臂 IK；超过肩肘最大伸长时人物需要移动到新站位，不能拉长手臂。双手举宝箱时降低跑动与跳跃能力；拿水桶时水质量改变动作重心和桶中水面角度。

### 6.3 船上行走与风浪

采用船局部物理世界：甲板相对船不动，玩家行走时以船局部坐标推进；向世界转换时叠加船体平移、旋转和局部点角速度。小幅船晃只影响腿/相机稳定，严重风暴才有脚底滑移、跌倒或主动抓栏杆；手握绳/舵进入固定岗位后不被甲板晃动直接抛走（极端碰撞除外）。必须在船移动时复现上梯子、登船和拿货物，严禁只在静止船状态测试。

### 6.4 落海、游泳、救援

玩家落水后有落水音、入水涟漪、浮力、呼吸/体力反馈与视角变化。攀爬船侧绳梯与船运动在同一坐标框架计算；若船离太远可利用救援小艇/同伴鱼叉协作救回。落海不应瞬移回甲板；死亡允许重生，但过程明确有状态、惩罚和可见位置。潜艇进出水也使用这一套 underwater 体积判定。

### 6.5 动作质量量化

设计目标：第一人称/近距同伴手掌偏离抓握点 ≤ 5 cm（关键帧时）、脚落地穿透不超过 2–3 cm（正常行走）、重要技能发力与命中事件时间误差 ≤ 50 ms、普通相机不得穿过角色头/衣服/墙板，持续 30 分钟试玩无“脚步空踩”高频现象。这些阈值是验收候选，应结合最终模型比例与帧率验证。

## 7. 船舶损坏、进水、消防、修复与真实沉没

### 7.1 不再用一条船的全局血条替代船损

将船分为艏、左舷中、右舷中、船尾、甲板/桅杆、舵、绞盘、船长室外壳等部位。弹丸/海怪接触创建有世界与船局部坐标的受损点。舷侧水线以下破口才持续进水；上层甲板破洞主要影响可行走表面与火灾，桅杆受击影响帆力，舵损坏影响转向。全局完整度仅用于 UI 概览。

### 7.2 舱段水体与救船操作

各舱段维护有效水体体积和连通规则；多个洞口按各自水压入水，货舱水位逐渐上升，桶必须亲自舀起且在船舷外倒掉；甲板雨水会沿敞开舱口少量流入。木板补洞停止该洞流量，但水不自动下降。水量增加船重量、重心偏移、横倾风险；船沉没时甲板与室内对象逐步倾斜，允许船员跳海，货物漂浮到正确位置。

**不得牺牲干舱逻辑**：无破口且没有溅入水，船长室和底舱不应出现一条来自无限外海的水面线。风浪可以把雨水、海浪从**开口**泼入，但需要接触规则与可见来源，不能无来源地从墙面透过。

### 7.3 烈火与修理

火源来自炮弹、落雷、灯具事故，热量与可燃物构成有限范围蔓延；船员可取水扑火，开门通风可能加速火势但提高可见度。初期简化为 5–10 个甲板火区即可，关键是能看到火源、听到报警、执行舀水→泼水、火焰变弱、修复烧毁设备的完整流程。

## 8. 航海战斗：炮术、站位与真实撞击

### 8.1 海战不是“远处互扣血”

船炮射击应要求船员实际装弹与瞄准。一次有效战斗的节奏：发现敌帆 → 绕至侧舷 → 调整帆角与转舵 → 对准射角 → 发射炮弹 → 观察落点 → 修补己方破洞/舀水 → 选择追击、登船或撤退。这种互相要求配合的环节才是海盗海战的主体。

### 8.2 炮弹类型与效果提议

| 弹药 | 主要目标 | 有效效果 | 限制/资源 |
|---|---|---|---|
| 标准实心炮弹 | 木质船壳 | 命中点破洞与结构伤害 | 基础补给，需一发一装 |
| 链弹 | 桅杆与帆索 | 使帆收缩/断裂并降低航速 | 重型，射程/弹道不同 |
| 散射弹 | 甲板人员、木制道具 | 近距离压制与小范围伤害 | 对厚船壳低效 |
| 烟幕弹 | 观察/战术脱离 | 形成短暂可见烟幕 | 持续时间短，不直接伤害 |
| 钩索鱼叉 | 船、礁石、宝箱 | 拉近距离或牵引实体 | 受拉力与索长限制，可能断裂 |
| 幽焰弹（后期） | 特殊幽灵舰体 | 压制幽灵防护，可能引火 | 稀有耗材，非万能弹 |

初期纵切片只需要标准炮弹、链弹和可用鱼叉，确保弹道、碰撞、破坏和同步真实；其他弹种必须建立在稳定物理之上。

### 8.3 近战、登船与滑动船板

玩家可以从船侧梯登上敌舰；在移动船上近战，剑击伤害基于武器碰撞体/攻击窗口和角色位置。敌人可以击退到栏杆但不得直接穿栏杆掉进海面；落水由实际越过边界决定。登船者可尝试放锚、偷货、破坏补给，但所有行为经服务器权限校验。初期敌舰优先 AI 控制，PVP 为后续迭代。

## 9. 任务系统：五类完整可游玩的新内容

每个任务必须有可见接取入口、实体目标、多个动作节点、失败/撤退、结算、再次可玩。不是纯“抵达坐标自动完成”的区域脚本。

### 9.1 任务 A：失踪的海图师（首次合作出航）

**入口**：潮汐港船长室地图台上的一封损坏信件。**目标**：寻找沿岸失踪的海图师小艇。**任务步骤**：船员接任务并在海图圈定海域 → 起锚拉帆离港 → 望远镜找到漂木与海鸟 → 调整帆低速接近 → 用鱼叉拉回漂流箱 → 玩家下水取失踪日志 → 返回船，放到船长室阅读 → 发现第二个小岛坐标 → 返回港口交付。**失败**：日志落海未消失，可凭浮标重新找回；沉船后日志变漂浮救援物；不需要强制传送。

**细节**：信件可拿在手里、靠近光源阅读；鱼叉拉箱是物理缆索操作；同伴可操舵让船慢速维持角度；路上可能有小雨，但不得在首次教学中突然刷终极海怪。**验收**：1 人可独立完成、2 人分工效率更高，临时断线重连后目标/箱子仍在正确位置。

### 9.2 任务 B：破帆的商船（真实修船与救援）

**入口**：码头商人发布求救线索。**步骤**：远处烟雾定位 → 进入侧风区 → 小心接近受损商船 → 登船发现两处真实破口、积水 → 一名玩家拿板修理、一名舀水、另一名稳船 → 将商人货物装入己船货舱 → 护送至安全航道。**随机变量**：破口位置、风向、货物重量、附近海盗是否来袭。**风险**：救援中天气变恶劣，玩家需决定先救船还是先搬货。

### 9.3 任务 C：幽灯之夜（团队海战）

**入口**：港口灯塔异常燃起绿光；船员从海图取得舰队航线。**步骤**：夜航寻找幽绿色灯标 → 用望远镜识别幽灵船 → 靠近、保持侧舷射角 → 破坏三处幽焰桅灯防护 → 将实体幽影匣拉上甲板 → 在返回途中防守幽灵小艇登船 → 交给港口术士。**玩家分工**：掌舵/帆索/炮手/维修兼鱼叉。**验收**：绿灯是光源与体积雾效果，不是漂浮的发光光球；幽灵船有完整船体、炮口与导航轨迹。

### 9.4 任务 D：风暴航标（航行控制）

**入口**：港口船匠需寻找远海失联航标。**步骤**：提前在图台选择两条航路 → 船员读取风向、减少主帆迎浪面积 → 绕过雷区/礁石 → 进入风暴带寻找断裂航标 → 下水修复/更换灯芯 → 原路返回。**关键机制**：大浪真实改变船艏垂向运动，驾驶员需要控制方向，船舱不会凭空进水；极端风况可能绞盘过载。**失败与重试**：船被雷击可修复，航标恢复进度保留但不直接发奖。

### 9.5 任务 E：深渊回声（深海魔鲸号与利维坦）

**入口**：完成前三类任务后可获得深海信标图。**步骤**：收集声呐部件 → 在船坞真实装配潜艇装备 → 帆船驶至安全深渊边缘 → 角色从船甲板/码头进入潜艇 → 下潜，灯光寻找沉船残骸 → 避开海底岩壁与利维坦巡游区域 → 采集回声晶体 → 观察利维坦的警告姿态 → 选择回避或开启 Boss 战 → 上浮回到母船/港口。

**设计重点**：潜艇不是另一份脱离世界的游戏画面；进入后共享房间世界时钟、坐标系、海怪位置和任务进度。全黑故障必须通过深度曝光/灯光/碰撞 QA 阻断；任何时候保留上浮、返回安全深度和撤退路径。

## 10. 海怪生态：先做可信的身体，再做巨大数值

### 10.1 统一 Boss 定义

每只怪物必须有 `BodyRig`（骨骼与形变）、`HitVolumes`（身体/头/触手可击中）、`Sensors`（视觉、水声、噪声、领地）、`Brain`（行动状态）、`AttackTimeline`（动作与真实命中）、`PhysicalResponse`（船/人受冲击）、`Reward`（战利品实体）、`NetworkReplication`（位置+骨骼关键点+技能事件）。若只有模型和血条不可称为完成。

### 10.2 五个 Boss 差异化设计

| 敌人 | 核心运动 | 攻击及触点 | 反制 | 必需可见效果 |
|---|---|---|---|---|
| 大白鲨 | 水下 S 曲线游动、加速冲锋 | 牙口命中船舷/水中玩家 | 望远镜预警、鱼叉阻挡 | 尾摆、鳍切浪、咬合时水花 |
| 大王乌贼 | 头部缓游、触手多段 IK | 抓住船舷后拉扯/掀翻、喷墨 | 刀砍触手、舷炮打头 | 每条触手真实卷绕、有握持点 |
| 三头魇龙 | 躯干游动+三头独立寻敌 | 每颗头选不同甲板目标，咬击 | 团队同时干扰不同头部 | 三颈张力与口腔咬合，不拉伸贴图 |
| 巨型海龟 | 慢速升沉、转向有重量 | 壳撞与短期水漩防御 | 避开正面，攻击露出弱点 | 壳体受波冲击、鳍真实划水 |
| 利维坦 | 长距离游弋、尾/鳍协同，深海盘旋 | 口咬、尾击、水炮与声呐冲击 | 潜艇机动、声呐诱饵、甲板炮协助 | 巨大身体遮挡海光，攻击判定随骨骼 |

### 10.3 攻击状态机与“接触才伤害”原则

`PATROL → PERCEIVE → WARNING → CHASE → TELEGRAPH → COMMIT → CONTACT_WINDOW → RECOVER → REPOSITION`。怪物每次攻击必须经历可辨认的前摇（鲨鱼加速、乌贼触手抬起、三头龙后仰、利维坦张口）。在 CONTACT_WINDOW 期间，服务器/权威房主检测**骨骼端点 swept capsule 与船体碰撞层交点**。未接触就判定 MISS，绝不只因“距离船不足 30 m”直接扣损坏；击中后从交点创建船壳损坏/人击退/碰撞浪花。

特殊远程攻击（墨汁、水炮、冲击波）可独立采用实体投射/体积波前，前摇仍要明确，伤害区随真实波前传播，而不是瞬间扩大到全船。

### 10.4 乌贼“抓船”完整微观时序

0.0–0.8 s：乌贼在船侧露头，触手在水下产生旋动浪迹；0.8–1.5 s：一条触手出水，IK 探索船舷可抓取插槽；1.5–2.0 s：触手 tip 碰到舷侧，物理锁定一个抓点，发出木材压裂音；2.0–4.5 s：持续拉扯，在船体局部接触点施加拉力/力矩，角色可用刀击打贴住船板的触手；接触断开触手回弹并滑落入海；没有抓住则攻击失败，并进入重新定位。**所有时间为样例，最终随动画与手感调优。**

### 10.5 巨兽骨骼与网格质量

大怪物不能把整段身体用单一拉伸网格伪装。制作模型时提供自然生理结构、连续法线、足够多的运动控制节（例如乌贼长触手每条可配置 12–24 段控制点，利维坦躯干 18–32 段主控制骨；这是制作预算建议，不保证骨越多越好），配合曲线 IK、体积保持和皮肤权重校验。逐帧检查尾鳍掠过身体、头颈相互碰撞、口部闭合和船板接触位置，低配 LOD 可减少骨骼计算但不可令近景动作突然定格。

### 10.6 多人首领同步

客户端只提交武器命中尝试、位置/动作；权威节点判定生命值、技能阶段、接触点和伤害；每个关键打击是事件 `{attackId, creatureId, boneId, contactPoint, targetId, impulse, damage, serverTick}`。联机玩家均可看到相同击中时刻与船舶反冲；死后掉落的奖励是服务器创建的实体，不能在每个客户端各掉一份。

## 11. 幽灵船与敌舰队：像真实船一样遵守海面规则

幽灵船不是一张漂浮贴图；必须沿同一波浪采样表更新俯仰与滚转，具备最基本的质量、转向惯性、帆（可带超自然效果但有规则）、船壳命中、炮位、破坏状态。敌舰 AI 采用 `patrol → investigate → approach → broadside → recover → flee/sink`，拥有避礁、避免船间穿模、保持舷炮射界、近距离登船与撤退决策。

幽灵视觉特色：半透帆与铁锈船体相结合，灯火发绿光并照亮真实木板，雾中有渐进的可见轮廓；幽灵炮弹有明显弹道/命中点。不能把模型整体透明到丧失碰撞可信度。每个敌舰至少一个可识别弱点部件（灯、帆、炮塔），使玩家与普通木船的战斗区别明显。

## 12. 海岛：真正可进入的生活化港口、村庄、灯塔

### 12.1 主岛不是背景布景

从码头到酒馆、船匠、市场、灯塔、村民小屋与岸边仓库应存在连续可走道路；房屋开门后内部有实际桌椅碰撞、楼梯、二层与可用货架。村民具有重力/地面法线约束、导航网格和坐姿/工作位，不得出现悬空行走或脚底滑行。小型陆地 Boss 具有全身模型、骨骼、真实攻击前摇和可规避轨迹，而不是用巨大光球占位。

### 12.2 五类关键 NPC 与完整行为

| NPC 职业 | 日常行为 | 玩家交互 | 网络共享 |
|---|---|---|---|
| 船匠 | 木工桌、搬木板、修船 | 购买木板、修理受损机关、升级船配件 | 交易由服务器发奖/扣款 |
| 海图师 | 研究地图、路标观察 | 发布打捞与探索任务、接收海图 | 任务进度按队伍同步 |
| 商人 | 摆摊、整理货箱 | 物资交易、收购货物 | 防物品复制、同队结算 |
| 灯塔守望者 | 日落点灯、风暴时报警 | 海上警报、启用信号航标 | 灯塔光效和事件状态一致 |
| 酒馆船员 | 坐下、谈话、巡街 | 船员招募、世界传闻、休整 | 招募名额/岗位锁定一致 |

每个 NPC 行为由真实站点（work/sit/patrol）驱动，可播语音或文本，必须提供站立与转身、对视、走到目标点的连续动作。复杂自由文本 AI 对话仅为可选高级功能，基础任务不依赖外部付费 API，离线也能完成。

### 12.3 灯塔、码头和船上灯光

灯塔必须使用合理可见尺度、可攀爬台阶/内部结构、昼夜自动亮灯、光束随旋转扫向海面。港口夜间应具有可识别的暖色航标与水面反光；船的灯笼能逐盏打开/关闭，甲板可用于夜间操作。风暴中的灯光受雨雾衰减，不能被全屏 bloom 放大为实心光球。

## 13. 潜艇：把“深海魔鲸号”做成第二种真实载具

### 13.1 与帆船不同但控制一致的原则

保持统一的鼠标视角（鼠标水平移动只控制相机朝向，除非进入明确的驾驶视角），方向操作接近主船：W/S 前进后退、A/D 转向，额外 Q/E 或自定义键上浮下潜；注意 E 在步行状态是交互键，**进入潜艇驾驶状态后才切换为升降**，UI 明确提示并允许重新绑定。原游戏常见的问题是鼠标左右与船/潜艇朝向相反，本设计统一 yaw 符号和镜头灵敏度。

### 13.2 潜艇物理参数建议

舵效速度相关、水平阻尼、纵向浮力与水舱压载共同确定运动；上浮/下潜速度有限且加速有过渡；速度仪显示 m/s 或节并标注单位，绝不硬编码数值；潜艇上限速度在可控推进档可略高于利维坦普通巡游速度，但低于其短冲锋速度，使追逐有张力。初版示例速度目标：潜艇巡航 4–6 m/s、急速 8–10 m/s，利维坦巡游 3–5 m/s、冲刺 11–13 m/s（均为待调优假设，不是现有实测）。

### 13.3 深渊视野与光照

使用水下体积雾+散射、可调探照灯、船体仪表、声呐回波，而非“深度增加就直接把画面乘以黑色”。深海战斗时可看见潜艇的鼻端、仪表、前方 10–30 m 的有限视觉区域，手电开/关与电量有真实反馈；环境能保持神秘但不能导致完全不可操作的黑屏。灯、涡流、海底障碍和利维坦轮廓要分别有不同识别途径。

### 13.4 进出舱与共同世界

必须从帆船/码头实物入口进潜艇，并在潜艇内存在可见的舱门和驾驶位；离开驾驶位后人物能在安全室内活动。潜艇与母船共享世界坐标、房间时间、任务、海怪状态；载具之间切换不能删除另一艘船的物理状态。发生深海紧急情况时提供抛压载上浮、修理漏水、启动备用灯等可互动自救选项。

## 14. 海洋视觉、天气与声场设计

### 14.1 海况级别与操作关联

| 海况等级（设计参数） | 视觉 | 船运动 | 交互影响 |
|---|---|---|---|
| 0 平静 | 小幅长涌浪、清晰水平线 | 轻微 heave | 登船/装货简单 |
| 1 微风 | 小浪花与旗帜轻摆 | 轻微 roll/pitch | 新手驾驶 |
| 2 中等 | 风向明显、偶有白沫 | 船首抬落 | 需主动调整帆角 |
| 3 强风 | 高浪、斜向雨、帆绳绷紧 | 侧滑、转向吃力 | 装炮可能中断，舀水重要 |
| 4 暴风 | 云墙、雷、密集喷雾 | 偶发破浪冲击 | 帆损风险、重装备操作慢 |
| 5 极端 | 漩涡、破碎浪峰、低能见度 | 拉力/冲击显著 | 需队员协作防沉与脱离 |

海面着色器、船物理波高查询、浪花方向、泡沫和声音必须使用统一海况与风场；不能视觉看见三米大浪而船毫无起伏。用户在舱内看到的是干舱/实际舱底积水，不是世界外海海面的切片。

### 14.2 关键音效层

`ambient_sea` 远景海水、`hull_creak` 船板受力、`rigging` 索具紧绷、`anchor_chain` 锚链转动、`cannon` 发射/装填/命中、`bilge` 滴水/涌水、`storm` 风雨雷、`ghost` 低频耳语、`leviathan` 深水低频回声；声源位置绑定实际实体，船舱空间用遮挡低通/混响区分，水下用高频衰减与声呐音突出危险。不得以一段循环 BGM 替代因果声效。

## 15. 原创美术方向、材质预算与资产许可

### 15.1 视觉语言

关键词是“冒险童话式夸张 + 可信的木铁绳帆结构”。船体可继续是复古荷兰帆船，不要求和《盗贼之海》一模一样；但每个关键操纵点必须在远处能识别：舵轮轮廓、绞盘轮廓、舷炮炮口、帆绳、瞭望塔、甲板灯光。主视觉用海蓝、赭木、铜铁、暖灯与幽焰绿作为体系，避免把高亮 UI / 彩色材质叠成杂乱画面。

### 15.2 建模和拓扑质量门槛

外观模型可高细节，碰撞模型应精简但封闭；需要正确的法线/UV/材质贴图、门口双面厚度、炮架可动部件、锚链引导锚座、人物骨骼和命名 socket。任何几何开洞必须更新碰撞与遮挡；任何拾取道具必须有世界模型与手持模型，不能用纯 UI 圆标表示。

### 15.3 分档性能与材质预算（建议目标）

| 项目 | 中档桌面 WebGPU 目标 | 高档桌面目标 | 退化策略 |
|---|---|---|---|
| 帧率 | 1080p 60 FPS 优先 | 1440p 60 FPS 优先 | 动态分辨率、云雾/粒子降级 |
| 角色蒙皮 | 同船 4 人始终完整 | 高细节骨骼+IK | 远景降低 IK 频率 |
| 海怪 | 近景保留攻击关键骨骼 | 多层次肌肉/尾迹 | 远景 LOD 动画，不可关键时刻冻结 |
| 灯光 | 灯笼关键局部光与阴影 | 更多接触阴影与体积雾 | 关闭远光阴影，保留工作区可见性 |
| 海洋 | 基础 FFT + shore foam | 增加多尺度浪峰与水花 | 降低水花粒子和反射精度 |
| 内存 | 保守预算、加载任务必需资源 | 高质量纹理选择性常驻 | 岛屿/动画/怪物按需流式加载 |

预算应由真实 GPU profiler 与动态场景实际测量决定。参考 Rare 在 GDC 关于动画动态加载和最坏情形内存监控的公开介绍 [S7]，新资源不能无限堆叠常驻显存。

## 16. 玩家成长、物资、经济和船型

### 16.1 核心资源循环

海上寻找 → 持有/搬运 → 装船 → 航海面临损失风险 → 返港兑现 → 购买实用升级与外观 → 进入更危险海域。奖励分**可消耗物资（木板/炮弹/食物）**、**船只模块（灯塔镜片、声呐、锚机齿轮）**、**外观装饰**、**声望/金币**。避免高等级船数值完全碾压新手，使多人协作技巧仍是核心。

### 16.2 经济平衡候选

| 物品 | 建议单位价值（仅首次模型） | 作用 | 风险 |
|---|---|---|---|
| 普通货箱 | 60–100 潮币 | 教学与补给 | 低 |
| 沉船日志 | 120–200 潮币 | 解锁线索 | 中 |
| 风暴航标核心 | 250–400 潮币 | 高级航线升级材料 | 高 |
| 幽影晶核 | 400–650 潮币 | 特殊灯具/弹药/装饰 | 高 |
| 深海回声晶体 | 700–1100 潮币 | 潜艇声呐/照明升级 | 很高 |

物资与金币交易由服务器处理，`rewardTxnId` 去重。单人失败应损失部分未兑现货物，但保留已获得的永久外观与解锁，不制造过度惩罚。

### 16.3 船只梯度

不立即实现多艘巨型船。先使当前荷兰船成为功能完整的 1–4 人船；稳定后添加小型 1–2 人快艇和中型炮舰。快艇转向快、载货少；荷兰船载货与协作均衡；重型炮舰侧舷火力强但操作笨重。每一种船都要有可走甲板、真实舵/帆/锚/炮和碰撞，不能仅更换模型贴图后沿用相同交互点。

## 17. 单人、双人、四人的可玩性与 AI 补位

| 人数 | 工作分配 | 玩法设计约束 |
|---|---|---|
| 1 真人 | 玩家可在舵、帆、炮、修理间切换；AI 最少维持安全航线/观测 | 不能因为无人转四个绞盘就完全无法起航 |
| 2 真人 | 舵/炮、帆/维修按战况切换 | 不能要求第三名真人才能完成任务 |
| 3 真人 | 舵、炮、帆兼维修 | 协作效率明显提升，不制造额外 AI 挤占岗位 |
| 4 真人 | 舵、炮、帆/锚、维修/瞭望，紧急时全部转锚 | 四人可以同时真实操作绞盘、也能分散在甲板 |

AI 船员不是服务器里一个永不移动的假人：必须实际走到岗位、操作相同机制，真人接管时让岗；AI 帮忙但不能替玩家自动完成核心任务。无网络也能把 35–45 分钟首航流程走通。

## 18. UI / UX：让玩家视线回到实体世界

### 18.1 情境界面

角色闲逛时 HUD 简洁；准星指向绞盘时出现 `E 抓住把手`，抓住后显示 `W 收锚链 / S 放锚链 / Esc 离开` 和真实链行程；拿木板时只高亮能修的洞；进入炮位后才显示 `R 装填 / 鼠标瞄准 / 左键开炮`。所有提示与当前位置、库存、状态一致，不能从一个旧 UI 模板无条件播报。

### 18.2 地图、任务和船员沟通

地图台在世界里可互动；打开地图后是立体海图/俯视图，可标记坐标、任务岛、风暴边界、危险传闻与船员 ping。房主与船员可共同标记，使用不同颜色/图案区分；标记的地理坐标与天气/任务系统同源。地图应显示航程方向、未必提供全程自动路线，保留观察和驾驶的探索感。

### 18.3 失败反馈

锚机不能使用时明确显示“离绞盘太远 / 该把手有人使用 / 锚链卡住 / 尚未完成加载”；开炮失败显示“未装弹/装填中/炮口受阻”；下梯失败显示“下方被箱子堵住”；穿门失败显示“请蹲下/门未开/前方有人”，不能仅让 E 无响应。

## 19. 音乐、镜头与可访问性

游戏节奏主要来自海浪、绳索、木板、怪物和同伴声音；背景音乐在海上探索时轻量，风暴和海战时进入动态分层音乐。镜头有关闭晃动选项、色弱友好指示、按键重新映射、字幕和音效强度选项；动作眩晕风险控制：船体晃动时摄像机可适量稳定、转舵不强行锁死玩家鼠标、潜艇沉降速度有渐变。

## 21. 示例协议、任务状态机与防穿模判据

### 21.1 任务蓝图数据（示意）

```ts
const mission = {
  id:'lost_cartographer', recommendedCrew:[1,4],
  prerequisites:['first_ship_ready'],
  stages:[
    {id:'accept', action:'vote_at_chart', count:1},
    {id:'depart', action:'anchor_raised_and_sail_power', count:1},
    {id:'spot', action:'spyglass_identify', target:'driftwood_01'},
    {id:'recover', action:'physical_harpoon_pickup', target:'log_crate'},
    {id:'stow', action:'place_in_hold', target:'log_crate'},
    {id:'deliver', action:'sell_at_outpost', target:'log_crate'}
  ],
  authority:'server', uniqueRewardKey:'mission_instance_id'

```

与位置相关的步骤必须由真实物理行为和服务器合法性判断完成：`depart` 要确认确实起锚且船被帆力驱动离开码头，不是把任务变量手工设为 true。进度持久化时保存各 stage 的事件来源，掉线不会重复触发。

### 21.2 动作/伤害时间线（示意）

```ts
interface AttackEvent {
  attackId:string; actorId:string; poseTime:number;
  type:'bite'|'grapple'|'cannon'|'shockwave';
  contactWorld?:{x:number;y:number;z:number};
  targetId:string; validated:boolean;
  damage:number; impulse?:{x:number;y:number;z:number};
}
```

重要规则：`poseTime` 控制动画，`contactWorld` 来自碰撞系统，`damage` 由权威节点计算；不允许本地客户端在无物理命中时直接发 `validated:true`。同一 `attackId` 在服务端只生效一次。

### 21.3 反穿模的必要测例

船静止/航行/15° 倾斜、天气 0/5、船舱干/湿、角色空手/携宝箱/持炮弹、双人同时通过，每组合都检查：胶囊没有进入封闭三角面、门扇没有与玩家互穿、相机不会穿船壳、所有室内水仅来自实际破口/开口、角色换层后仍有实体落脚点。必要时建立 debug 叠加显示 BVH、角色胶囊、门口 portal、海水 clip volume、攻防 hitboxes，给每次 BUG 定位一条证据链。

## 24. 验收矩阵、失败处理与量化目标

### 24.1 各新内容“算完成”的门槛

| 内容 | 完成条件 | 不合格现象 |
|---|---|---|
| 主船 | 船身可走、所有必要设备可操控、物理与动画一致 | 船自动开走、船舱进海水、舵轮被墙挡住 |
| 货物 | 取放、搬运、舱内储存、出售、多人同步 | 贴图箱、物品重复、存入后消失 |
| 海战 | 装填→瞄准→真实弹道→命中→破洞→修船 | 只扣全局血条、炮管不转、无限弹 |
| AI 船员 | 移动到设备、正确让岗、可见操作 | 站桩假人、HUD 写“在岗”但没动作 |
| 天气 | 风浪影响船、画面、声音、多人同步 | 只有屏幕特效，船完全不受影响 |
| 海怪 | 皮肤和骨骼质量合格，接触才扣血 | 巨大光球、僵硬摆动、隔空咬船 |
| 潜艇 | 真实上浮下潜、视角正常、仪表真实、可撤退 | 速度不变、黑屏、相机反向、卡死 |
| 村庄 | 人贴地，门/楼梯/家具可达，能接任务 | 浮空村民、建筑空壳、只播对话框 |
| 多人 | 2–4 人同步位置/天气/装备/任务/船损/AI | 各自世界独立、无动人偶、时间不同 |

### 24.2 性能和可靠性目标（提案，非实测）

1080p 推荐级 60 FPS，90 分位帧时 ≤ 20 ms；首航 45 分钟内 0 次主线程挂死、0 次无退出路径软锁；船舱/门/楼梯常见操作下 0 次可复现碰撞穿透；2–4 人联机正常网络下连续 30 分钟无显著时间天气分裂；20 次连续上/下舱、10 次多人同时绞盘、10 次敌舰破洞修补、10 次海怪抓船均可复现。对目标设备不支持的性能门槛，应标明未测，而不是默认 PASS。

### 24.3 Bug 严重性

P0：无法航海、船舱有贯穿海水、模型/角色严重穿透、多人世界根本不一致、开局无法正常交互；P1：装备/任务/怪物核心动作不真实、卡住但可恢复、严重视觉闪烁、重复发奖；P2：材质/声音欠佳、细节不足、局部动画不自然；P3：装饰优化与小幅 UI 文案。P0/P1 必须在新增内容上车前关闭。

## 25. 对已有代码的集成验收与交付标准

### 25.1 不允许开两套世界逻辑

新任务复用 `VoyageM1` 现有可行的收集/存货/兑现事务，但把任务扩展为数据驱动图；新幽灵船复用 `EnemyShipController` / `GhostFleet` 的导航/绘制入口；新巨兽复用 `TitanAI` 的追踪与领地逻辑，但追加骨骼接触判定；新潜艇基于 `SubmarineDynamics`，而不是复制一套 `BoatController` 并让键位互相冲突；新岛屿 NPC 基于 `LandResidents` 和 `LandVillageNavigator`，并将全队可见任务状态提升为共享权威状态。

### 25.2 资源包交付

每个里程碑需同时交付：源码工程、资源授权清单、可复现的独立 Python/Node 测试入口、Windows 真实 GPU AutoQA 报告、逐项 PASS/FAIL 表、关键操作 30–60 秒短视频、性能报告、已知问题清单和回退版本。一个版本最多有一套当前生效主船资产；旧版模型可备份但不可被场景重复加载造成穿模。

### 25.3 本提案的“不做清单”

不做未经验证的“自动无 Bug”承诺；不做只因场景截图好看就标记“AAA 级完成”；不做缺乏命中实体的直接扣血；不做玩家走不到的船长室/灯塔；不做通过隐藏海洋掩盖船内进水；不做带版权风险的直接复制；不把新功能全部塞进 1000 行单文件。始终优先完成**一个真实闭环**。
