# STORMWAKE V57 — 真正共享联机状态（V56 → V57）

## 启动

双击 `00_START_V57.cmd`，选择以下三种模式之一：

- **单人**：仅运行本地游戏，无需 Node。
- **创建房间**：运行本地游戏（127.0.0.1:5173）及房间主机（0.0.0.0:5174，WebSocket），Node.js 22+ 必需；同一个 Wi-Fi/局域网下，Windows 防火墙应放行 **TCP 5174**。
- **加入房间**：本地运行游戏（127.0.0.1:5173），填写主机的 **局域网 IPv4:5174**，不是主机浏览器的 5173 端口，也不是自己电脑的 127.0.0.1 地址。每台电脑各运行自己的游戏启动器，以本机 localhost 打开 WebGPU 页面。

打开游戏后，左/右 UI 的 `👥 船员` 显示 **人数 · 同步**。如果显示离线、连接失败或人数不变，先核对地址和防火墙；此时不应声称多人成功。

## 本轮真正改变的源码

1. `server/coopHub.js`：房间服务器使用正式登记 + 首次有效坐标两步加入。成员加入通知为 `ready:false`，不会再在港口生成一个位置虚假的静止人偶。首次位置更新后才生成角色。每 250ms 广播 `room_snapshot`（完整有效角色 + 世界时钟），用全量快照纠正漏包/晚加入。
2. `src/oceanhunt/CoopClient.js`：真实人物脚底世界坐标、朝向、步行/奔跑/游泳/爬梯/舵位/岗位动作随网广播；海上共享船体不另建假的船只；多人角色采用分段四肢动画（替代单一静止几何体）。位置采用平滑纠偏，大距离传送立即对齐；进入/退出房间清理实体网格。
3. `src/net/SharedWorldClock.js`：服务器统一维护房间日序、24 小时制时钟、日夜速度、太阳方位角、天气演化相位、版本号。房主调整时间可广播；普通成员不能私自改变房间时间。客户端从服务器快照恢复，页面打开先后和帧率不再单独决定昼夜及风暴。
4. `src/App.js`：每帧用服务器房间时钟设置太阳、整体视觉时钟、风暴区域天气及海洋 FFT 相位；显示参数不再独立平滑成不同目标。**同一世界坐标**按一致输入得到相同风雨；不同岛屿/海域仍遵守区域性天气（非全世界同一场雨）。
5. `src/course/HomeLife.js`、`src/ui/AppUI.js`：共同日序显示；房主可在 T 键或设置面板修改统一的昼夜。普通队员不能控制公用时钟。
6. `src/net/ShipNetBridge.js`：原房主断线、新房主接管时，使用服务器已知最后船体快照，避免船跳回第二名玩家本地出生点。
7. `server/coopServer.js`：房间状态 API 加入服务器世界时钟与已就绪人数，辅助定位“可连接但未真正加入”的问题。

## 重要边界

- 该版本实现多人位置、动作状态、同船舶运动、岗位指令、锚机、世界时间和区域性风暴天气共享，但 **并非整套 GTA/盗贼之海级别的完整权威 ECS**。部分原单人系统（个人背包、民居、陆地任务/NPC、部分巨兽之外的环境实体）仍使用个人本地存档/逻辑，不能声称全部互动已经服务器化。
- 人物动画目前是程序化四肢动画和姿态变化，不是完整动作捕捉及 IK 动作库。存在视觉上限。
- 本环境具备 Node WebSocket 实际双客户端通信测试和角色场景节点的逻辑测试，但未通过受限浏览器中的双机 WebGPU 帧渲染测试。不同 GPU/驱动上的显示、贴地、穿模和通信延迟，仍需要实际两台电脑按下面清单验收。

## 两台电脑实机验收

1. A 创建房间，B 加入房间。确认双端船员按钮显示 `2/4 · 同步`，并能看到对方活动的海盗角色（不要把 AI 船员当成真人）。
2. 两人都留在码头。A 左右走、跑、跳，B 观察相对位移和面向变化；然后交换角色；在船舷及船舱再验收。
3. A、B 一起登上一条船，A 驾驶，B 从船首跑向船尾，不应固定在船体原点；B 进入舵位，A 退出后可接管。两人分别操作不同锚机岗位，锚链行程与船体位置保持共同状态。
4. A 修改为 23:00，B 应在片刻内看到相同夜色；再切到 07:30，B 的时钟显示同步。B 尝试修改，服务器会拒绝；可在 A 离开之后转移房主权限。
5. 一起航向远海风暴：同一海域内风向、风速、云量、浪高趋势与天气变化应一致；不同海域可出现区域性差异。B 中途加入，获得当时的昼夜与房间船舶状态。
6. 房主退出，剩余玩家接任，测试船不瞬移；房主重新打开新房间则是新的会话，不保留之前内存中的房间状态。
7. 如人数不同步，检查房主的 `http://127.0.0.1:5174/api/crew/status`，检查返回的 `players`、`readyPlayers` 和 `world`；同时看浏览器开发者工具中 `/crew-ws` 的 WebSocket 连接是否成功。

## 自动测试

安装 Node.js 22+ 并在根目录执行：

```
node test/stormwake-v57-real-multiplayer.mjs
npm run test:v57
```

专项覆盖两条真实 WebSocket 通道的角色位姿互发、服务端周期快照、暂停/恢复时钟、天气输入一致、后加入快照、权限隔离、房主接管、三维人物四肢动画及清理。旧版 54/55/56 的船舶交互测试保留。
