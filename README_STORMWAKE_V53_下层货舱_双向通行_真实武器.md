# STORMWAKE V53：主船下层货舱、船长室双向通行与武器系统修复

## 本次依据

本版本基于 V52 完整源码直接修改，不是只有文字方案。保留原始 Dutch Ship GLB 的 hull/rigging/sails 与原船门板，保留 TheMadraver 船长室授权模型；沿用原引擎 WebGPU/JavaScript 源码与现有游戏机制。没有重新生成第二艘船替代原船。

### 1. 主甲板真正进入下层货舱（与船长室分开）

- `public/models/stormwake_v53/dutch_ship_lower_hold.glb`：在 V52 原船船壳主甲板原三角面上**切出新的贯穿开口**，保留其余船体、UV、材质、桅索与帆模型。不是靠透明贴图伪装的洞。
- `src/ship/DutchLowerHold.js`：在原船壳内新增船内衬板、下层木质地板、支撑梁与真正可见的梯横档，舱底局部船体坐标为 `y=-0.63`，货舱可行走纵向区间约 `z=-4.95 ~ +3.48`。这些内部衬板是为了连通船舱而新增的结构性网格；**它们不是原始 Dutch Ship 作者提供的独立舱底网格**。
- 主甲板新货舱口约在原船局部坐标 `x=0, z=-3.65`，在主船甲板中段偏船尾；站到舱口中心按 `E` 或 `C` 下梯。舱内可自由移动、可实际存放/拿取货物；回到梯口按 `E`/`C` 返回主甲板。
- 这条路径使用 `deckLayer='lowerHold'`，不再错误地借用船长室 `deckLayer='hold'`。
- 开口持续无甲板碰撞面。上梯时先纵向上升，再横向落到 `x=+0.82,z=-3.65` 的**实心原甲板**，不会回到原洞口直接坠落。

### 2. 船长室不再有进无出

- 船尾船长室与新货舱是两个独立空间。
- 船长室尾楼舱口梯可双向攀爬；上梯终点移到 `x=-0.64,z=-7.43` 的实心原尾楼甲板。
- 原 Dutch Ship 船尾隔舱壁上拆出的原门板，室内和室外均有 `E` 交互。第一次 `E` 打开原门，再次 `E` 经原门洞上/下结构台阶通行；原门保留原材质与铰链动画。
- 船长室原模型的实际空间与床、桌、椅、箱子碰撞继续保留。门槛台阶是新增的实用木结构，不是新造一扇门。

### 3. 船舱海水线处理

- 所有下舱空间（`hold` 和 `lowerHold`）均使用干燥舱室摄像机逻辑，避免角色在空气舱内切入水下后处理。
- 原船本地坐标的水面剔除体积覆盖两个舱室，同时保留船壳外侧海面，不使用全局关闭世界海洋的粗糙解决办法。
- 以上为 shader/相机代码路径修复，尚**未**通过真实 WebGPU 浏览器逐角度观测证实 100% 无海水像素或特殊波况水线。

### 4. 大炮可操作、瞄准与发射

1. 靠近船舷炮位，按 `E` 上炮位。
2. 鼠标移动调整准星，或 `A/D` 左右转动炮口、`W/S` 控制仰俯角。
3. 鼠标左键发射。弹体从当前炮管的方向附近生成，跟随瞄准角度与船速，撞击采用已有船战弹道与目标系统。
4. `R` 装填，受炮弹库存与装填计时约束；再按 `E` 离开炮位。
5. 已有船体伤害、破口和维修状态逻辑继续共用，不是点击后简单播放特效。

### 5. 现有甲板武器不再只是看得见的摆设

- 原工程已有的船首捕鲸叉、长枪架、望远镜架、风暴炮位置接入 `E` 选取/装备。只有解锁/拥有的武器能装备；原成长与素材条件不被绕过。
- 在甲板未操作炮位时，`F` 发射当前猎兽武器（望远镜为按住观察），`T` 循环切换已拥有武器，`K` 打开锻造/军械面板；若正在使用短刀，`K` 保留重击，军械面板通过屏幕按钮打开。
- 这些发射物实际进入 `HuntCombat.updateProjectiles` 并调用 `SeaBosses.hitProjectile`，不是纯展示动画。短刀可按原项目 `1` 装备并用鼠标战斗。
- 装备长枪/望远镜后，模型会从对应装备架消失，以表示被取下。船首大型安装捕鲸叉仍显示为固定装置。
- `F`/`T` 在航海模式优先让武器使用，避免旧版自由镜头/时间切换劫持键位。

### 6. 已有灯光与船锚

- 延续 V52：原船灯根据昼夜自动亮灭，不需要手动按开关；功能性船锚仍关联真实船只抛锚/起锚状态。

## Windows 启动

1. 将完整 ZIP 解压到英文路径（例如 `D:\Games\STORMWAKE_V53`），确保项目文件在同一目录下。
2. 双击 `START_STORMWAKE_V53.cmd`。
3. 需 Windows Python 3.10+、Chrome/Edge WebGPU。启动器不依赖 npm/Vite 安装。
4. 如果 5173 端口被占用，命令行运行 `python start_v53.py --port 5179`。
5. Linux/macOS：`python3 start_v53.py`。
6. 需要开发/构建时：安装 Node/npm 后 `npm ci`、`npm run build`。本交付环境的依赖安装尝试超时，故打包以源代码直启为主。

## 测试与明确限制

- `npm run test:v53`：V53 新增 10 项专项断言 + V52/V50 及更早版本回归链，运行通过。V51 专用历史模型 `dutch_ship_operable.glb` 不再是 V53 运行所需资源；为控制单 ZIP 大小，发行包省略了这一份旧网格快照（如果确需重做 V51 历史验收，可使用附带的 `tools/build_v51_source_door.py` 从保留的 V50 原始资源再生）。对历史测试中“上梯必须落在舱口中心”这一已知错误断言作了注明并更新为“落在实心甲板”，没有把修复改回旧故障。
- 检查了新增 GLB 的 SHA256、三角形开口拓扑、材质与桅索保留。新增的主甲板开口不遮掩原封闭甲板面。
- 修改过的 JavaScript 已通过 `node --check`；全部源文件也执行语法检查。
- 通过 Python 本地服务请求确认了源码、GLB 和船长室模型均可访问。
- 自动化 Chromium 在当前运行容器中访问本地页面时返回 `ERR_BLOCKED_BY_ADMINISTRATOR`，无法运行 WebGPU 页面逐角度游玩/截图验收。因此**不能保证没有新的穿模、镜头遮挡、碰撞边界或海面渲染问题，更不能称为商业 3A 完美成品**。
- 货舱使用有限的内层衬板、地板和空间约束，而不是原船作者提供的一整套内装；未实现货舱内完整的舱门、炮弹装卸动画、多人同步舱内存物。小艇也尚未从原 Dutch Ship 大网格中分离并做出可驾驶实体。

如在本机真实浏览器游玩发现某个位置卡住，请记录发生时人物附近部件、位置、操作键和截图，以便定位几何具体区域；源码里保留了该版本回归测试，可以重复验证。
