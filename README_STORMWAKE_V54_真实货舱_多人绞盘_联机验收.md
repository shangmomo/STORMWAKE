# STORMWAKE V54 — 真实货舱、原船绞盘、船长室入口和多人联机修复

基于用户 V53 完整工程修改的完整源码版。请从 V54 启动文件进入游戏，不要继续运行 V53 启动器。

## 启动

**单人**：Windows 双击 `START_STORMWAKE_V54.cmd`，或在工程根目录执行 `python start_v54.py`。需要 Python 3.10+ 和支持 WebGPU 的 Chrome/Edge。游戏页面 `http://127.0.0.1:5173/?stormwake=1&heritageShip=1`。

**多人房主**：双击 `START_STORMWAKE_V54_COOP.cmd`，或执行 `python start_v54_coop.py`，需要 Node.js 22+（用于无额外 npm 安装的 WebSocket 联机服务）。保留房主的命令行窗口，TCP 5174 是多人联机端口。房主页面也需在船员面板连接 `127.0.0.1:5174`。

**多人加入者**：每个人各自在自己电脑双击 `START_STORMWAKE_V54.cmd`，打开本地 WebGPU 页面（127.0.0.1:5173），点击右上方船员面板，在“房间服务器”输入 **房主的局域网 IPv4 地址:5174**（例如 `192.168.1.20:5174`），然后加入。确保房主 Windows 防火墙允许 TCP 5174。不要直接用异机 HTTP LAN 页面打开 WebGPU：非 localhost 的非 HTTPS 页面可能不属于安全上下文。

## 本版修复及坐标依据

### 1. 货舱入口不再与绞盘重合

- 基于原 Dutch Ship CC0 模型 GLB 三角面重新制作船体，而非简单放置一个黑色洞口遮罩。
- **撤销 V53 错误的中央货舱洞口**，中央实心甲板恢复；在**主甲板侧边步道**（船体局部坐标 x≈−0.86、z≈−2.18）切出真正贯穿原甲板网格的开口，避开位于 x≈0、z≈−3.65 的原船绞盘。
- 人物站在舱口旁**实心甲板边缘**就可按 `E` 或 `C` 下梯，不必走到洞口中央坠落。上梯后返回舱口旁实心甲板。
- 甲板下面是独立 `lowerHold` 层，配置实心底板、内衬、支撑和可攀爬梯，与船长室 `hold` 层严格分开。
- 注意：下层内壁、龙骨底板和梯子作为原外观船模的结构补件制作，不能声称其是原始 GLB 中已存在的独立部件。

### 2. 船长室与舵轮分离

- 取消船长室**尾楼顶部旧舱口梯**的可见模型，屋面原旧洞口加盖，避免梯子与船舵/轮舵互相遮挡。
- 船长室改为从船尾**原 Dutch Ship 隔舱壁门板**进入（E 打开、再按 E 进门）；出门同理从内侧 E 打开/踏过门槛回甲板。
- 保留船长室下载模型与海图，没有替换成一套新外观的房间。
- 房间顶部舱口不再作为船长室入口，不能按 V53 的旧提示去找入口。

### 3. 舱室海水横线

- 之前仅有局部水体遮罩。V54 在相机处于密封舱室时，直接暂时停止绘制**世界海面**，防止 FFT 水面在船长室及下层货舱内切出横向亮线；回到开放甲板后立即恢复海面。
- 副作用：从密封室内向船外窗户观察时，远处水面暂时不会显示，这是有意识的临时视觉取舍；最终高保真做法需要基于真实体积/深度的舱内水面剔除。未完成实际 WebGPU 截图验收，不保证不存在其它材质造成的亮线。

### 4. 船锚改为真正绞盘旋转

- 原船 GLB 中中央绞盘顶部的 132 个源三角面被分离成可旋转 `original_dutch_capstan_turntable` 节点，源材质/纹理 UV 仍使用原资源，不再使用一套另造的绞盘外观替代。
- 绞盘周围有四个独立玩家操作位 `anchor`、`anchor_2`、`anchor_3`、`anchor_4`，多玩家可同时使用，无需两人竞争同一个 E 位置。
- 靠近绞盘侧面的可操作位置按 `E` 入位；**持续按 W 起锚，持续按 S 放锚**，松开停止。1/2/4 人同向操作时，起放锚速度近似按人手数提升。`E` 退出操作；`R` 恢复自动锚泊策略。船锚升降与绞盘圈数绑定。
- 房间内由房主计算锚链进度/转数/参与人数，并向其他玩家同步；不是各客户端独立模拟。
- 说明：物理锚具仍沿用工程既有的授权锚资源；原 Dutch Ship GLB 没有可直接分离的锚节点。绞盘旋转模型来自原 GLB，锚具本身不是。

### 5. 多人联机

- 测试包括：真实 TCP/WebSocket 三人建房加入、三个独立绞盘操作位认领、同时 W 转动输入转发、权威锚链状态同步、文本聊天、原船门开关跨客户端同步以及迟到加入者得到门状态。
- 继续运行旧版已实现的回归：四人房间容量和第五人拒绝、队友位置同步、远程舵/帆、远程火炮、服务器防作弊校验和共享敌人状态。
- 改进：自由行走的船员上报**自身世界位置**，不再把所有甲板玩家上报在船体原点或固定货位。
- **未实现/未验收**：多人货舱内宝箱的持久空间取放仍存在保护性禁用分支；真实多电脑 WebGPU 同船穿模、客户端延迟补偿、长时断线恢复未完成验收。若要将这些算作“完美联机”，仍需下一轮实现及真机联测。

## 当前按键

| 场景 | 操作 |
|---|---|
| 主甲板侧边货舱口 | 站在洞旁的实心甲板，`C` 或 `E` 下梯 |
| 下层货舱梯 | 靠近梯子，`C` 或 `E` 上甲板 |
| 船尾原门 | `E` 开门，再 `E` 穿门进入船长室；室内反向同理 |
| 绞盘臂 | `E` 入位；按住 `W` 起锚；按住 `S` 放锚；`R` AI；`E` 离开 |
| 舵轮 | `E` 入位，`A/D` 转向、`W/S` 调推进；`E` 退出 |
| 大炮 | `E` 入位，鼠标或 `A/D` 左右、`W/S` 俯仰，左键发射，`R` 装填 |
| 船员联机 | 打开船员面板，连接房主的局域网 `IP:5174` |

## 实际执行过的测试

- `npm run test:v54` 通过：8 个 V54 专项测试 + 真 TCP/WebSocket 三人交互联测；V39 航程 M1 20 项、V39 双人岗位、V41 远程火炮、V13 4 人房间/第 5 人拒绝、V14 远程炮弹测试均通过。
- 船体 GLB 校验：与记录 SHA-256 一致；原中央甲板恢复有实体三角面；侧边新开口内部缺少源甲板面；原有门节点和新增绞盘旋转节点存在。
- JS `node --check`，Python 编译，离线启动器的 HTTP 页面及船体 GLB 访问检查已执行。
- **未通过浏览器实景 WebGPU QA**：本环境 Chromium 的 EGL/OpenGL 初始化失败，不能真实渲染截图，也无法手动驾船逐一测试所有碰撞和多人画面。不要将代码测试通过误认为已经完全“没有穿模”。
- `test/v54-run-results.txt` 留存本次回归输出。旧 V50 的部分旧断言要求船长室顶部舱口一直开放，这与 V54 正确关闭旧入口的设计矛盾，因此没有强行复活旧断言，只运行相关兼容测试。

## 资源与许可

沿用 V53 原完整工程的原始模型、纹理、授权记录及素材。不额外安装第三方 npm 包即可运行单人 WebGPU 源码和基于 Node 内置 HTTP/WebSocket 的多人房间。

打包去除了 V53 旧的 28 MB 船模副本（当前游戏不再读取；V54 使用新船体 GLB）。其他当前游戏运行资源与授权文档保留。由于旧 V53 专项测试需要那份历史副本且旧入口设计已改变，请使用 `npm run test:v54` 验证本版。
