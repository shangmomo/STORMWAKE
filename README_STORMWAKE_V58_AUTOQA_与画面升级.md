# STORMWAKE V58 — 自动游玩验收与画面升级

> 完整源码工程。以用户提供的 V57 Multiplayer Fixed 为基础。
> **这是自动验证基础设施与针对性美术升级，不应被称为已达到《盗贼之海》3A 品质或实现零 Bug。**

## 01. 一键运行

- `00_START_V58.cmd`：与 V57 一样，选择单人、房主或者加入房间（运行时不依赖 npm/Vite）。
- `00_RUN_AUTOQA_V58.cmd`：自动使用 Python 启动本地游戏和真实 5174 联机服务器，运行 Playwright Chrome/Edge 浏览器测试。默认 2 个独立浏览器上下文。首次运行会尝试安装 `playwright` 与 `Pillow`；如浏览器提示缺少驱动，安装 Chrome/Edge 或执行 `python -m playwright install`。
- `00_AUTOFIX_V58.cmd`：**完全可选**。仅在有真实失败证据、用户主动同意、Codex CLI 已安装及登录时，允许有限次数的自动源代码修复和复测。不能自动更新已发布游戏，也不能无限期后台运行。
- 备用命令：`python tools/autoqa/runner.py --quick --headed`（只运行单客户端的快速验收）；`python tools/autoqa/runner.py --headed`（完整双客户端）。`python tools/autoqa/runner.py --existing` 可连接已有 5173 / 5174 服务器。

**依赖：** Python 3.10+、真实支持 WebGPU 的 Chrome/Edge 与显卡、WebGPU 显卡驱动。完整双客户端须有 Node.js 22+，同时请预留足够 GPU 显存。项目逻辑测试仅需 Node.js。Windows 自动运行器会尝试调用 Chrome，找不到则调用 Edge。

## 02. 验收系统新功能

`?qa=1` 只在本地开发服务上开启以下 API；正式构建中不会启用：

- `window.__stormwakeQA.snapshot()`：玩家坐标、地形/上船模式、舱室层级、舵轮模型、船锚行程、当前锚机人数、主帆、动力、天气相位、昼夜时刻、灯光数、Boss 加载状况、远海生物、联机玩家目标坐标和可见性。
- `window.__stormwakeQA.check()`：自动检查无效位置、异常时钟、锚机状态、无人偶/联机握手、舵轮是否存在、船舱角色极端坠落等。
- `window.__stormwakeQA.go('anchor' | 'helm' | 'cabin' | 'lower_hold' | 'boss' | 'open_sea' | 'dock' | 'spawn')`：**仅限 QA** 的测试定位。这些传送不等于用户能物理通行；正式验收仍需用键盘正常走路、转锚、进出船舱。
- `window.__stormwakeQA.setHour(21.4)`：单人使用本地时刻，联机仅房主可通过服务器控制共享时间。
- `window.__stormwakeQA.events()`：异常事件队列，最多保留最近 150 条。

`tools/autoqa/runner.py` 启动真正的浏览器而非模拟 DOM，自动抓取每一个场景的 PNG、JS 错误、网络失败、Playwright trace 和可用时的 WebM 视频。完整模式还用**真实键盘 E/W**测试锚机及舵轮、真实键盘移动、两个联机页面的远端角色与共享时间天气。截图会自动检测黑屏/白屏/近单色，船舱过量青色像素只标为**可疑**，而不是直接认定有水。

生成的报告位于 `autoqa_reports/V58_日期时间/`：

- `VISUAL_REPORT.html` — 图文报告与截图相册；
- `REPORT_zh.md` — 便于阅读的测试总结；
- `report.json` — 结构化失败证据，供编码代理定位；
- `screenshots/`、`video/`、`captain_trace.zip` / `crew_trace.zip` — 如浏览器与 FFmpeg 允许生成。

**证据分级：** `pass` = 该逻辑断言通过；`fail` = 可复现失败；`suspect` = 像素或视觉异常，仍需人工/模型复核；`unverified` = 运行环境不支持该项。禁止把 `captured` 的截图等同于“画质过关”。

## 03. 本版实际美术和游戏修改

1. 六盏甲板灯具改为一体化金属笼、顶盖、底盖、玻璃灯芯、悬挂环与橡木支架；全部合并为一个绘制批次，不叠加漂浮物。
2. 夜间局部照明改为**从真实灯具的坐标派生**，不再光从空气中来。灯光采用暖光、微弱烛火闪动，独立的红绿航行灯保持低亮度。
3. 去掉灯塔任务完成后出现的实体青色球体；保留实际灯塔发光元件，防止把发光实心几何体误当成光晕。
4. 修复沉船救援后的旧状态覆写：船不再自动恢复 35% 动力和张开的帆，玩家在陆地重生，船等待人工起锚。
5. 更新启动画面品牌和操作提示，将过时的 `E` 一键起锚说明改为真实的 `W/S` 机械起降。

仍然属于待完成的美术工作：完整 PBR 资源审查、船舱网格/水密性重构、人物全身动画、海怪接触攻击、GPU 真实光照迭代和影视级天气变化。**仅凭这一版源码修改，不能保证达到《盗贼之海》画质。**

## 04. 本地验收结果和未完成边界

此生成环境可以运行源码和 Node.js 逻辑测试，但自动化 Chromium 无法加载 `http://127.0.0.1:5173/`（浏览器报 `ERR_BLOCKED_BY_ADMINISTRATOR`），并且缺少 Playwright 视频依赖 FFmpeg。Python HTTP 服务可正常响应；自动测试器会把浏览器失败明确记录为 `fail`，不会伪造画面通过。需要在你的 Windows GPU 上执行完整双客户端报告。

`node test/stormwake-v58-autoqa.mjs` 覆盖 QA 校验、错误状态、时钟一致性、四人绞盘模型状态及美术布局静态约束。`npm run test:v58` 会继续运行完整的 V57/V56/V55/V54 相关逻辑回归。

## 05. 自动修复循环的安全边界

自动修复器只在**浏览器和 WebGPU 真实初始化成功**时才会尝试针对失败项改源码，并限制为最多 2 次（可配置 1–4 次）。它会在每轮前保存 `src/`，禁止自动修改 QA 测试、结果判定和源素材；出现回归未改善时恢复原有源码。使用 Codex CLI 的 `workspace-write` 沙箱，不启用无防护全权限。请注意本地 CLI 会占用你的模型额度，且任何自动修复都可能产生新 Bug，建议在独立工作目录中操作。

**商用画质验收需要独立美术标准：**真实纹理分辨率、单场景帧时预算、主船内舱结构、材质反射、动捕/骨骼动画、人物与海水接触、视觉叙事及镜头构图。自动化只能减少重复操作，不能替代以上制作。
